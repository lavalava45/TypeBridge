# TypeBridge: roadmap

Обновлено 27 октября 2026 года. Здесь — оставшиеся задачи, ограничения
и критерии приёмки. Реализованные функции и история изменений:
[CHANGELOG.md](CHANGELOG.md).
Наличие функции в коде или сборке не означает совместимость со всеми приложениями.
Очередь ниже не является разрешением автоматически реализовать каждый пункт.

## Текущая версия

- **27.10 — управляющие символы шаблонов (этап 4: поведение зафиксировано,
  риск не устранён).** Модельные тесты подтверждают, что текстовый `\n`
  преобразуется в Unicode `\r`, табуляция остаётся Unicode `\t`, без физического
  `VK_RETURN`/`VK_TAB` внутри текста. Однако разделитель Enter/Tab отправляется
  как физическая клавиша, а принимающее приложение вправе интерпретировать
  Unicode CR/TAB как действие (отправка сообщения, формы, смена поля).
  Ложное обещание в комментарии исправлено; инструкции RU/EN/HE предупреждают
  об ограничении. **Без испытаний на реальных приложениях семантику передачи
  менять нельзя:** универсально безопасного переноса строк для всех чатов нет.

- **27.10 — нетекстовые окна (этап 3, частично).** В `LiveHook.context()`
  отклоняются известные классы списков, деревьев и навигации Windows,
  в том числе нетекстовые поверхности Проводника; его нативное поле `EDIT`
  (например, переименование) не исключено. RichEdit, Scintilla и браузерные
  виджеты по-прежнему доступны. Это не универсальная проверка способности
  произвольного нестандартного контрола принимать текст; поддержка браузеров
  не отключалась. Безопасность действий в реальном Проводнике требует
  отдельной физической приёмки, не подтверждается только моками.

- **27.10 — Scintilla Undo (этап 2, частично).** После подтверждённого
  `SCI_BEGINUNDOACTION` всегда выполняется одна ограниченная (15 мс) попытка
  `SCI_ENDUNDOACTION`, даже если `SCI_REPLACETARGET` либо установка каретки
  завершились таймаутом. Текст не исправляется повторно; результат остаётся
  неопределённым. Если сам `BEGIN` завершился таймаутом, факт открытия группы
  не установлен, а безусловное закрытие может затронуть чужую группу.
  **Остаток:** проверить Undo/Redo и восстановление после реального зависания
  на Notepad++ без глобальных тестовых hooks и без риска для документов;
  модельные тесты не подтверждают фактическое закрытие группы после таймаута.

- **27.10 — снижение риска потери WH_KEYBOARD_LL (этап 1, частично).**
  Обычный ручной цикл последнего слова (Pause и настраиваемый аналог) теперь
  использует уже существующий off-hook клавиатурный worker вместо прямого
  `SendInput` и ожидания HKL до 180 мс внутри callback. Проверены моделью:
  фокус/DOM-ревизия, отказ запуска worker, очередь следующих клавиш и KEYUP.
  **Остаток:** это не доказательство постоянной работоспособности Windows hook;
  в обычной сборке нет независимого подтверждения потери hook и автоматического
  восстановления. Другие пути callback и физический быстрый ввод требуют
  отдельной проверки; публичный release gate остаётся BLOCKED.

- **Известное ограничение P0, принято для экспериментальной alpha-ветки,
  но не устранено:** общий UIA `PasswordFieldGuard` сейчас не подключён
  к `LiveHook`. Проверяются известные процессы менеджеров паролей и
  стандартный Win32 `EDIT` с `ES_PASSWORD`; парольные поля браузеров и
  нестандартных контролов достоверно не определяются. Автокоррекция, раннее
  исправление, ручная конвертация и шаблоны могут изменить секретный ввод.
  При включённой диагностике слов возможна запись символов, включая пароли.
  Работа в браузерах **намеренно не отключается**, код исправлений не меняется;
  вопрос полной защиты **отложен, а не закрыт**. Это не разрешение на
  стабильный релиз. Подробности: [PRIVACY.md](docs/PRIVACY.md).

- Аудит `AUDIT-RU.md` 26.10 №17–20: при сохранении во время загрузки
  словарей выигрывает последняя сохранённая конфигурация; после частичного
  Ctrl+V выполняется балансировка всех принятых KEYDOWN без повтора вставки;
  повреждённый ICO восстанавливается и постоянные ошибки трея ограничиваются
  по частоте, не крадут фокус. Документация debug теперь требует перезапуска
  после удаления `TypeBridge-debug-words.flag`. Тесты №21 обновлены
  по действующим правилам без возврата удалённой защиты паролей или старого
  выбора неоднозначных слов. Публичный Git-релиз пока BLOCKED.
  Итог фоновой проверки №21: 59 модулей / 621 тест пройдены раздельными
  процессами; source/frozen self-test и нативные стенды на неактивном desktop
  успешны. Это не подтверждает физический ввод, быстрый набор и Undo на двух ПК.
  Публичный сборщик также переведён на изолированный запуск тестовых модулей,
  чтобы не накапливать память больших словарей на Windows runner.

- Аудит `AUDIT-RU.md` от 26.10: в исходниках устранены модельные сценарии
  №13 (DOM-поле с тем же HWND), №15 (исключение после принятой замены),
  №14 (автоповтор буквы) и №16 (KEYUP-only не сбрасывает токен). Для браузера
  автоматическое воспроизведение и ручной возврат удержанных букв после
  смены ревизии запрещены, даже если родительское окно не поменялось.
  Остаётся физическая приёмка на обоих ПК; No01 не разблокирован.

- Повторное исправление №13: удержанные физические клавиши исходного поля
  можно явно восстановить из временного буфера через трей, когда снова
  выбраны тот же HWND/процесс и ожидаемая раскладка (до 180 секунд). Не
  выполняются слепая доставка в новое поле, возврат управляющих комбинаций
  или восстановление уже частично отправленных пакетов. Проверка итогового
  текста и каретки в физических приложениях ещё необходима.
- №4: известный отказ ввода ограничивает исходное RichEdit-поле; глобальный
  карантин остаётся при неопределённой записи. Трей показывает ограниченный
  режим отдельно от общего статуса «работает».
- №10: Git остаётся намеренно грязным: исходники и новый EXE локальны, но
  публичный выпуск остановлен проверкой `git status` до сверки и коммита.

- Повторный аудит `RECHECK-FINAL-RU.md` (26.10): P1 №13 предотвращает
  **поглощение ввода уже нового поля** при смене фокуса во время off-hook
  нативной транзакции. Барьер отцепляется и пропускает последующие клавиши,
  но ранее задержанные клавиши старой цели нельзя гарантированно восстановить
  после ухода фокуса; это сигнализируемая потеря и release gate всё ещё
  `BLOCKED` до физической проверки. P2 №12 (slow-success ≠ uncertain),
  №6 (пустые confident-файлы) исправлены. №11 в штатном worker уже был
  устранён увеличением лимита до 32. Публичная сборка отныне блокируется
  при грязном Git; полнота релизного коммита пока не обеспечена.
- Открыто после сверки: №4 — глобальный карантин RichEdit и его отдельное
  отражение в трее; №10 — полное внесение проверенных файлов в Git и
  повторяемая публичная сборка; №13 — восстановление ранее удержанных
  клавиш при смене поля без безопасного адресного транспорта и реальная
  физическая приёмка обоих компьютеров.

- Аудит переносимости и замены текста от 25.10: в исходниках закрыты
  воспроизведения P1 №1/№2 (передача SendInput и проверка поля) и P2
  №4/№5/№6/№7/№8/№9; для №10 добавлена автогенерация build manifest.
  P1 №3 (**длинная нативная транзакция внутри callback**) остаётся
  архитектурно открытым; fallback HKL ещё требует физической приёмки на
  разных профилях Windows. No01/R01 — BLOCKED до реального теста ввода.
- P1 №3 — промежуточная реализация: синхронный RichEdit-commit допускает
  не более 12 символов и расчётную оценку ≤700 мс **до начала записи**.
  При отказе слово не трогается; завершённая медленная операция (≥200 мс)
  отключает дальнейшие нативные операции. Исследование одного
  `EM_REPLACESEL` в private desktop подтвердило некорректный Undo для HE,
  поэтому быстрый транспорт нельзя вводить без отдельного решения для
  Undo/Redo. Остаётся вынести полный commit из WH_KEYBOARD_LL с защитой
  от параллельной физической печати; не считать этот пункт закрытым.
- 26.10: вариант off-hook для RichEdit внедрён в исходники (worker +
  bounded physical-input queue) и проверяется без глобального keyboard hook.
  Транзакции на границе слова, раннем KEYUP и Pause больше не вызывают
  посимвольные `WM_CHAR` непосредственно из hook. Резервный inline guard
  остаётся; физическое тестирование под быстрым набором, переключением
  окон и Undo/Redo на втором ПК обязательно перед снятием release gate.
- Дополнительная защита ввода: `SendInput` через общий `LiveHook`-маршрут
  перепроверки контекста и ограниченной однократной досылки остатка
  распространяется также на сниппеты, ручное переключение в обычных
  полях и ранний generic-путь. Принятые события не повторяются, незавершённые
  нажатия освобождаются. Физическая проверка двух компьютеров по-прежнему
  обязательна; generic-поля без API чтения не подтверждают текст после записи.
- Диагностическое наблюдение `post-early-deferred`: чтение документа в
  тестовом Блокноте перенесено из low-level hook в GUI queue, со сверкой
  целевого окна. Снимок может быть сделан **после** разделителя и следующих
  букв, поэтому не должен интерпретироваться как мгновенное состояние при
  нажатии Space. Событие `post-early-at-boundary` оставлено для совместимости
  с уже собранными старыми журналами.

- `main` и локальный `dist/TypeBridge.exe` включают переносной профиль,
  восстановление проверенного префикса, досылку остатка SendInput,
  правку повторных UIA-уведомлений и прокручиваемые настройки с подсказками.
- Локальная версия использует словарную допустимость, уверенность совпадений
  и заданный приоритет RU/EN/HE **без числового частотного арбитража**.
  Открытый RU FrequencyWords + Hunspell и архивные частотные индексы лежат
  рядом с EXE в `dist/data`, но `frequency_*.tsv` при запуске не читаются.
  Это локальная установка, **не** опубликованный релиз или коммит в `main`.
- Последний проверенный публичный релиз —
  [v0.1.0-alpha.5](https://github.com/lavalava45/TypeBridge/releases/tag/v0.1.0-alpha.5).
  Изменения после него перечислены в разделе «Не выпущено» changelog.
- Запрет автоматического чтения истории буфера без определяемого владельца
  теперь также включён в локальный EXE. Отдельный риск чтения уже скопированных
  секретов остаётся.
- До установки нового RU прошли полные регрессии 383/383 на открытой и 383/383
  на локальной конфигурациях в изолированных тестовых каталогах; после установки
  прошли 36 узких тестов и самопроверки source/frozen EXE (6/6 направлений).
  Физический ввод и все транспортные сценарии пока не приняты.

## Очередь и ограничения

Номера **R01–R15** — постоянные ссылки на задачи этой очереди.
Выполненные части оставлены внутри задач,
чтобы было понятно, какой именно остаток предстоит сделать.

### Надёжность и ближайшие проверки

1. **R01 — Совместимость ранней замены. Частично готово.** Сохранить работающие
   Scintilla/RichEdit-пути и проверить общий транспорт в типовых полях браузера,
   Windows Settings/Electron и обычных редакторов. Пользователь подтвердил
   ChatGPT/Notepad++ с продолжением `приветик ` и Блокнот на нескольких языках.
   Остаток: быстрый ввод, Undo/Redo, Backspace, границы слов, смена фокуса/HKL,
   отсутствие потерь/дублей; Total Commander после правки OEM-знаков ещё не принят.
   Универсальная совместимость не доказана; исходный gate No01 остаётся BLOCKED.
   25.10 (интерфейс второго ПК): зарегистрированный в Explorer tray-icon
   не гарантирует видимость в области уведомлений; прежний `withdraw()`
   оставлял окно без доступной кнопки восстановления. Обычное сворачивание,
   крестик окна и автозапуск переведены на безопасный `iconify()` с кнопкой
   TypeBridge на панели задач; иконка окна отображает язык RU/EN/HE.
   Win+Space выводится как стандартное системное сочетание, а отсутствие
   дополнительных HKCU shortcuts больше не считается ошибкой чтения.
   Тесты проверяют отсутствие скрытого окна, но фактическая видимость
   значка трея на втором ПК по-прежнему определяется настройками Explorer.
   25.10 (архив второго ПК, 18:40): readback подтвердил, что дубли последней
   физической буквы появлялись ПОСЛЕ `verified` нативной замены. Безопасный
   RichEdit-ранний путь перенесён с KEYDOWN с поддельным `WM_CHAR` на KEYUP
   после фактического появления полной физически набранной последовательности
   в редакторе. Отказ до записи, если чтение не подтвердило доставку. На
   неактивном desktop все шесть направлений до пробела работают; нужны новые
   физические испытания второго ПК, в том числе без лишней буквы.
   25.10: пользователь обнаружил накопление смешанных RU/EN/HE букв при
   повторных нажатиях Pause. Для RichEdit и Scintilla ручной цикл переведён
   со слепого SendInput на подтверждаемую нативную замену диапазона; если
   ожидаемый текст или каретка не совпали, запись отклоняется. Для других
   приложений цикл по SendInput пока не подтверждает состояние документа;
   проверка физического ввода и R03 остаются открыты.
   25.10 (следующий журнал): обнаружены многократные реальные тайм-ауты
   нативного `WM_CHAR` на 10-мс пороге (`ERROR_TIMEOUT 1460`), после чего
   запланированный защитный карантин блокировал даже распознанное `ntktuf`.
   Для изменяющих сообщений установлен отдельный лимит 35 мс, для чтений
   оставлен 10 мс. Нельзя считать проблему исправленной без физической
   проверки и анализа временного `debug-words.log`; No01 остаётся BLOCKED.
   25.10: политика редких слов синхронизирована с ранним распознаванием:
   включённая опция разрешает полное однозначное редкое слово (5+ букв)
   до пробела, но не угадывает незавершённые редкие префиксы. Физическое
   подтверждение на проблемном ПК и устранение дублей ещё требуются.
   25.10: пользователь отметил, что на втором ПК переключения участились,
   но появились повторные буквы. Включаемая отдельным флажком временная
   word-trace-диагностика позволяет сравнить `verified` readback и текст
   непосредственно перед разделителем. Проверка реального ввода остаётся
   необходимой; задвоение не объявлено исправленным.
   25.10: после воспроизведения частичных отказов RichEdit на втором ПК
   усилен запрет повторной записи после `uncertain`, а после отказа проверки
   каретки ранняя попытка откладывается до следующего слова. Бюджет 45 мс
   действует до начала нативной записи; каждый отдельный Win32-вызов остаётся
   ограниченным по времени. Эти правки требуют повторного физического теста.
2. **R02 — Первое слово после смены поля. Частично исправлено.** В прежней
   реализации повторные безопасные UIA-уведомления не сбрасывали слово;
   общий UIA guard в текущей версии отключён. Пропущенный префикс
   восстанавливается только из проверенного EDIT/RichEdit/Scintilla.
   Для браузерных/неизвестных полей без надёжного чтения первое слово всё ещё
   может пропускаться; отдельно исправлять его хвост нельзя.
3. **R03 — Частичная отправка и восстановление. Частично исправлено.** Одна
   проверенная досылка остатка уже есть. SendInput подтверждает доставку событий,
   а не состояние документа. Остаток: подтверждение результата там, где оно
   возможно; надёжный общий Undo/автооткат не реализован. Слепо повторять замену нельзя.
4. **R04 — Парольные поля и приватность. ОТЛОЖЕНО; защита неполная.**
   Общий `PasswordFieldGuard` удалён из действующего пути `LiveHook`;
   старые тесты не подтверждают его работу. В браузере парольное и обычное
   HTML-поле могут иметь один HWND. Требуется безопасная проверка конкретного
   элемента и повторная авторизация перед текстовой записью без ожидания UIA
   в клавиатурном callback. Обязательны испытания переключения между полями,
   обработки `unknown`, ручной конвертации, ранней коррекции, шаблонов и
   диагностической записи, причём физические клавиши должны проходить без
   задержки. До решения R04 безопасный ввод паролей не гарантируется.
   История буфера и дневник имеют свои независимые ограничения.
5. **R05 — Пользовательская проверка дополнительных функций.** Прямые сочетания,
   цикл Pause, CapsLock, флаг каретки в веб-полях, импорт, чистая вставка/история,
   шаблоны (переносы/Undo), запуск после входа в Windows и визуальная локализация.
   Скрытые/модельные тесты выполнены; повседневная приёмка этих сценариев неполна.
   Быстрый поиск из Notepad++ пользователь уже подтвердил; другие редакторы
   и восстановление каждого формата буфера этим не проверены.

### Распознавание языка и словари

6. **R06 — Контекст для коротких неоднозначных слов. Не реализовано.** В русской
   фразе выбирать `ye → ну`, в английской сохранять `ye`. Определить достаточность
   и сброс контекста при смене поля, каретки и ручном выборе языка; при недостатке
   данных сохранять ввод. Это не безусловный приоритет русского.
7. **R07 — Числовой частотный арбитраж. Отменён, из рантайма удалён.**
   Прежняя эвристика «частота лидера ≥2 на миллион и превосходство ≥20×»
   больше не участвует в выборе RU/EN/HE. Не загружать `frequency_*.tsv`
   при старте; достаточно словарной допустимости, confidence и приоритета
   альтернативных языков. Файлы частот, манифесты SHA-256 и инструменты
   воспроизводимого построения сохранены **как данные/исследовательские
   материалы**, а не как рабочие словари. Не выводить «частоты загружены».
8. **R08 — Качество и источники словарей. Частично сделано.** Бракованные
   конечные HE-буквы убраны в карантин. Оценить Hspell/обновляемые источники,
   современные написания и имена без потери полезных слов. «Поясни» уже добавлено
   явным дополнением при аудите 24 октября; продолжать исправлять подтверждённые
   пропуски без снижения общего порога уверенности ради одного слова.
   Открытая FrequencyWords/OpenSubtitles-база отличается от локальной: например,
   EN `lf` может блокировать «да». Локальные исследовательские RU/EN-словари
   из сторонней программы не распространяются. Источники и лицензии: [THIRD-PARTY.md](THIRD-PARTY.md).
   Проверены условия альтернативных RU-данных Лебедева и EN-данных SCOWL/Hunspell;
   прежний исследовательский русский список так и не опознан. Новый
   FrequencyWords + словоформы Лебедева/Hunspell установлен локально:
   1 485 012 записей, без использования неопознанного русского списка.
   Для английского старые списки
   International Ispell с аффиксами воспроизводят 134 461 из 134 485 записей
   (99,982%); остаются 24 локальных добавления и 16 отсутствующих у нас слов.
   Для независимой публикации этой основы нужно учесть её исторические условия
   распространения и явно разобрать отличия. Публичный ZIP
   alpha.5 содержит три открытых FrequencyWords-словаря с лицензиями.
   Новый местный набор с русской орфографической основой проверен перед заменой
   старого, но качество исправлений в повседневном живом вводе требует приёмки.
9. **R09 — Дополнительные языковые сигналы. Обсуждено, не реализовано.** Windows
   Spell Checking API как вспомогательная проверка; нетипичные сочетания букв
   как сигнал, а не самостоятельное доказательство ошибки. Это изменение
   распознавания, независимое от транспорта замены. Сначала оценка качества
   на примерах; работающий однозначный выбор сохранить.

### Дополнительные возможности

10. **R10 — Выделенный текст. Не реализовано для конвертации/добавления слова.**
    Добавить преобразование выделения с выбором смены/сохранения языка и добавление
    личного слова/исключения из выделения. Готовый поиск выделения не равен этим
    функциям; архивные заготовки требуют проверки перед подключением.
11. **R11 — Пропустить только текущее слово. Не реализовано.** Согласовать
    действие с ранним исправлением, Pause, Backspace и следующим словом.
12. **R12 — Обучение после отмен. Не реализовано.** Надёжно отличать ручную
    отмену/исправление от обычного ввода; затем счётчики, настройки и автоматические
    исключения после повторных отмен. Не менять словарь молча без такой основы.
13. **R13 — Дополнительные исправления. Не реализовано.** Двойной пробел,
    `ТАкое`, таблица орфографии, разделители чисел/времени. Расширения шаблонов:
    переменные, форматирование и единый Undo. Сейчас шаблоны — только текст,
    команды не выполняются. Расширения согласовывать отдельно.
14. **R14 — Словари узких специальностей. Частично готово.** Импорт есть,
    готовые медицинские/юридические наборы ещё не приложены. Импорт принимает
    отдельные слова, а не синтаксис языка/правила Hunspell или CSpell.
15. **R15 — Следующий публичный выпуск. Подготовить после приёмки.** Опубликовать
    переносной профиль и последние исправления через существующий workflow,
    полный unittest-набор, source/frozen self-test, ZIP и контрольные суммы.
    Windows-подписи пока нет; alpha.5 не содержит изменений из «Не выпущено».

## Границы текущих возможностей

- **Ранняя коррекция:** от четырёх букв для уверенного полного слова, от пяти
  для однозначного префикса; при включённой опции редких слов также полное
  однозначное редкое слово от пяти букв. Конкурирующий словарный префикс
  блокирует ранний выбор; числовой частотный арбитраж не применяется.
  Scintilla-путь ограничен UTF-8, 64 КБ и одной обычной кареткой.
- **Флаг каретки:** зависит от системной/Scintilla/MSAA-каретки; при неизвестных
  координатах скрывается. Не следует за мышью вместо текстового курсора.
- **Буфер:** история только в памяти, 30 текстов, до 100 000 символов на запись
  и 1 000 000 суммарно. Чистая вставка намеренно убирает HTML/RTF. Не каждый
  скопированный секрет получает системную метку приватности. В текущих исходниках
  автоматическая история не читает буфер без определяемого владельца; явная
  чистая вставка такого текста остаётся доступна. UIA-признак текущего фокуса
  не определяет происхождение уже скопированного текста.
- **Поиск:** UIA либо резервный Ctrl+C с предпросмотром и восстановлением
  поддерживаемых форматов (до 8 МБ/64 форматов). Связанные/встроенные OLE-объекты
  могут не поддерживаться. Сторонний менеджер буфера может увидеть копирование;
  запрос отправляется выбранному сервису только по команде пользователя.
- **Дневник:** снимки известных нативных полей каждые 2 секунды, до 64 КБ;
  браузеры не поддерживаются. Срок 1–365 дней (по умолчанию 7), лимиты
  50 МБ/20 000 снимков. Отключение прекращает сбор, но не удаляет старые записи.
  DPAPI привязан к учётной записи; перенос профиля не делает дневник переносимым.
- **Импорт:** UTF-8 TXT/JSON, до 2 МБ/50 000 записей; слова из 1–80 букв.
  Составные токены вроде `std::vector` не разбиваются и не импортируются как код.
- **Исключения:** точные имена процессов, а не распознавание любой IDE/программы.
  По умолчанию включены категории IDE/терминалов и творческого софта;
  незнакомые приложения можно добавить вручную.
- **Профиль:** требуется доступная для записи папка. Автозапуск нужно включать
  на каждом компьютере отдельно. Смена UI-языка не добавляет раскладки Windows.

## Критерии приёмки R01–R03

1. Исправление и смена HKL происходят до пробела при непрерывном вводе;
   нет пропавших, переставленных или повторных символов, хвост не обгоняет замену.
2. Меняется только отслеженное слово в прежнем поле. Перед записью проверяются
   контекст, каретка, граница и исходный префикс там, где доступно чтение.
   Выделение, readonly/password, смена поля, мышь, вставка, ручной язык и IME
   должны отменять операцию при потере уверенности. IME/режим замещения ещё
   не приняты как поддерживаемые сценарии.
3. Отказ до записи не должен терять обычную клавишу. После неопределённой записи
   нельзя слепо воспроизводить слово или переносить накопленный ввод в новое окно.
   Проверенная досылка остатка из R03 не является повтором принятой части пачки.
4. Проверены удержание клавиши, Backspace, модификаторы, немедленный пробел,
   следующее слово, ручной цикл, CapsLock, шаблоны и Undo. Собственные инъекции,
   подавленные keydown/keyup и физический хвост учитываются раздельно.
5. Отправленные события не равны подтверждённому документу. Даже наблюдение
   последнего собственного keyup не доказывает результат; нужны доступное
   чтение текста/каретки/HKL либо явно обозначенная граница доказательств.
6. Смена фокуса после части удалений может защитить новое окно, но оставить
   старое поле частично изменённым. Запрет записи в новое окно не обеспечивает
   атомарность. Не восстанавливать старый снимок поверх изменившегося документа.
   Внешний hook, съевший события, и завершение с неподтверждённым хвостом требуют
   отдельных сценариев; исследовательский стенд не решает их автоматически.
7. Буфер не используется для посимвольной автокоррекции, исключения сохраняются.
   Выключение экспериментального флага возвращает прежнюю маршрутизацию;
   отказ нового транспорта не должен отключать исправный путь Notepad++.

Если при смене поля/частичной записи нельзя сохранить перехваченный ввод,
такой сценарий не считается принятым. Нельзя устранять отказ сменой фокуса
без разрешения или объявлять отсутствие потерь по одному успешному API-вызову.

### Способы замены и границы расширения

Распознавание в `incremental_recognition.py` отделено от доставки; не менять
одновременно словари, пороги и транспорт. Экспериментальный общий путь использует
`early_correction` и `early_native`, второй флаг исходно выключен.
Нативная маршрутизация опирается на возможности поля, не на коллекцию имён EXE.
Прямой RichEdit-путь ограничивает запись печатными BMP-символами, 64 символами /
256 байтами, проверяет дедлайн и контекст между сообщениями. Эти ограничения
не являются общими лимитами всех текстовых функций.

| Способ | Роль и ограничение |
|---|---|
| Scintilla / NativeEdit | Проверяемая замена и чтение результата в поддерживаемых полях; сохранить работающую базу |
| SendInput | Общий клавиатурный путь; порядок в пачке не гарантирует документ, единый Undo или поведение хвоста |
| UI Automation | Метаданные/чтение, если доступны; TextPattern не редактирует, SetValue не заменяет безопасно участок документа |
| TSF | Возможное отдельное исследование, если общий ввод не выдержит критерии; не готовая универсальная замена и не текущая миграция |
| Буфер | Явный поиск/вставка пользователя; не запасной транспорт автоматического исправления во время набора |

### Фоновые стенды и ограничения запуска

Команды для отдельной проверки доставки из корня проекта; сами по себе
не доказывают физический ввод или качество словарного выбора:

```powershell
python -m unittest test_early_native_edit test_early_keyboard_probe -q
python early_native_harness.py --self-test
python early_native_harness.py --runtime-self-test
python early_keyboard_native_probe.py
```

Нативные стенды используют отдельные процессы и неактивный объект Windows
desktop на том же компьютере, без VM и воздействия на пользовательский desktop.
WM_CHAR/сообщения контрола не заменяют реальную SendInput-очередь.
Исторические отчёты стендов в `build/` не являются текущей приёмкой.

`early_live_trial.py` и `keyboard_transport_trial.py`
нужны только для отдельного разрешённого опыта в собственном пустом поле.
Открытие само по себе не включает hook; включение стенда и SendInput — уже
вмешательство во ввод. Перед опытом исключить конкуренцию с основным TypeBridge,
после — закрыть стенд и проверить снятие hooks. `--accept-injected` относится
к автоматизированному вводу стенда, не к изменению политики рабочего приложения.
Рабочие документы стендами не проверять. Локальная страница
`fixtures/keyboard-probe.html` содержит text/search/textarea/contenteditable/password;
её наличие не доказывает поддержку браузера, снимок не возвращает пароль.

Проверенные дефекты и результаты прежних опытов перенесены в
[CHANGELOG.md](CHANGELOG.md). Описание хранения и отдельных границ защиты:
[PRIVACY.md](docs/PRIVACY.md).

Синтетические и фоновые тесты не заменяют физическую приёмку. Работающую базу
до пробела сохраняем; новые проверки foreground и глобальных hooks требуют
отдельного разрешения пользователя.
