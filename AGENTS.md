# TypeBridge — обязательные условия проекта

Этот файл действует для задач и агентов в репозитории TypeBridge. Дополняет применимые локальные родительские инструкции и имеет приоритет перед устаревшими рекомендациями в отчётах и планах.

## Единственное место сборки

- Пользовательская сборка существует только по пути `dist/TypeBridge.exe`.
- Перед сборкой напомнить пользователю выйти из TypeBridge через «Выход» в трее; дождаться закрытия и проверить, что процесс завершён. Самостоятельно приложение не закрывать.
- Не создавать альтернативные EXE, каталоги `pending-*`, `updated`, `save-check` или дополнительные копии сборок/резервные EXE без отдельной просьбы пользователя.
- Использовать `build-typebridge.ps1`; работающий EXE не обходить сборкой в другую папку. Настройки и словари пользователя при очистке сборок не удалять.

## Запрет виртуальных машин для тестирования — решение пользователя от 19.10.2026

**В рамках TypeBridge не использовать виртуальные машины для тестирования.** Не предлагать и не планировать проверки в VM; не устанавливать, не запускать и не настраивать для проекта VirtualBox, Hyper-V VM, VMware, Windows Sandbox и другие виртуальные Windows-окружения. Не считать виртуальную машину обязательным условием приёмки или релиза.

Ранее подготовленные образы, результаты и упоминания VM являются только историческими сведениями и **не дают разрешения** продолжать этот путь. Если старые документы требуют VM, настоящая инструкция отменяет именно это требование, не отменяя сам критерий функциональной корректности и безопасности.

### Допустимые способы проверки

1. Unit, интеграционные и модельные проверки без вмешательства в текущий пользовательский ввод.
2. Нативные Win32 EDIT / HKL проверки в отдельном **неактивном Windows desktop на том же хосте**. Это объект Windows desktop, **не виртуальная машина**. Не активировать этот desktop, не изменять foreground, пользовательский HKL и поток клавиатуры.
3. REA/Ghidra, статический анализ, mock/fixture, синтетические `PostMessage`/`WM_CHAR` и другие безопасные фоновые испытания с явной маркировкой их ограничений.
4. Испытания на настоящем рабочем столе / физической клавиатуре — **только после отдельного явного разрешения пользователя**, строго в выделенных тестовых окнах и с защитой текущих документов и установленного SwitchER64.

**Недопустимо** выдавать синтетические сообщения, неактивный private desktop или прохождение unit-тестов за доказательство реального физического ввода в чужом редакторе. Если требование No01 не доказано без VM, оставлять соответствующий release gate `BLOCKED` и искать архитектурный или безопасный проверяемый путь без виртуализации.

Другие действующие ограничения проекта сохраняются: не запускать/останавливать оригинальный SwitchER64, не устанавливать глобальные hooks и не менять пользовательскую раскладку/фокус без отдельного разрешения. Приоритет No01 — распознавание и изменение HKL **до Space**, без потери, перестановки или дублирования символов.
