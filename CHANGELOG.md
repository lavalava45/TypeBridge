# Changelog

История изменений TypeBridge. Даты — даты разработки, а не обещание доступности
в каждом опубликованном EXE. Ограничения и планы:
[ROADMAP.md](ROADMAP.md). Инструкции: [RU](README-RU.md), [EN](README.md),
[HE](README-HE.md).

**Текущие исходники, 31.10.2026:** UIA-проверка конкретного поля подключена
к hook для браузерных/нестандартных контролов; общий запрет браузеров снят.
Исторические записи отражают прежние реализации. Атомарной гарантии между
UIA и DOM/SendInput нет: R04 остаётся открытым. Состояние опубликованного EXE
проверяется отдельно. См. [PRIVACY.md](docs/PRIVACY.md).

## Не выпущено — настольные редакторы (31.10.2026)

- Ранний клавиатурный путь отделён от карантина NativeEdit: отказ RichEdit
  больше не отключает автоматически исправление в других типах редакторов.
  Частичная клавиатурная отправка и неподтверждённый HKL сохраняют свой отказ.
- Добавлен допуск настольных UIA Custom/Pane/ComboBox при явном признаке
  редактируемости через ValuePattern или метаданные текущего TextPattern-выделения.
  Пароли, неизвестные состояния и пользовательские исключения сохраняются.
- 155 целевых + 45 регрессионных тестов успешны. Живая совместимость офисных
  и других настольных редакторов ещё требует приёмки; браузерная матрица отложена.
  См. [описание](docs/DESKTOP-EDITOR-COMPATIBILITY.md).

## Unreleased — field-level R04 browser regression fix (2026-10-31)

- Removed blanket browser/WebView/custom-editor exclusions. GUI/headless now
  obtain focused-element metadata for shared/custom fields; the optional UIA
  setting additionally checks native editors. ES_PASSWORD and app exclusions stay.
- Restored automatic/manual/cycle eligibility in verified ordinary browser fields
  and separated direct HKL selection from permission to change field text.
- Added worker-only pre-write metadata refresh; stale/unknown/password/different
  elements refuse mutation. Plaintext tracing stays suppressed with a guard.
- Scoped skipped-prefix tracking to the field that missed input, preserving the
  first word after leaving own/excluded windows or another unverified editor.
- Streamed the fixed UIA script through stdin to avoid Windows command-line
  overflow; no temporary script or execution-policy change is needed.
- Preserved Scintilla/NativeEdit transports and `f4cae1e` Undo behavior. UIA still
  has a non-atomic DOM-focus race; R04/physical acceptance remain open.

## Не выпущено — после v0.1.0-alpha.6

Изменения после публичного релиза; состояние локальной сборки проверяется отдельно.

### R16/4g — исправления P1 №10–12 после локальной сборки (29 октября 2026)

- ZIP-пакеты больше не могут использовать Windows drive-relative имена,
  двоеточия/NTFS ADS и обход staging; каждый извлекаемый файл проверяется
  через разрешённый путь до записи. Добавлены вредоносные ZIP-фикстуры.
- Установщик отказывается обновлять пакет при несовместимости нового
  алфавита с сохранёнными личными словами. На случай уже установленного
  несовместимого пакета загрузчик личного словаря переводит записи всего
  затронутого языка в сохраняемый карантин вместо срыва запуска. Повреждённые
  данные не скрываются; восстановление старого пакета возвращает записи.
- `TypeBridgeGui.save()` заново сверяет выбранные языки с актуальным
  verified-каталогом **до любых записей**: удалённый или изменённый пакет
  больше не попадает из устаревшего чекбокса в рабочий профиль.
- **Только исходники:** обе локальные Public/Diagnostics EXE были собраны
  *до* этих исправлений и их замена не производилась при работающих
  экземплярах. Физическая No01-приёмка остаётся отдельной блокировкой.
  Итоговая исходная регрессия после правок: **495/495 тестов, 55/55 модулей,
  0 ошибок**.
  Подробности: `docs/R16-4G-SOURCE-MODULARITY.md`.

### R16/4g — пакетный каталог в GUI, эффективные hotkeys и личный словарь (29 октября 2026)

- GUI inventory теперь берёт RU/EN/HE из проверенных bundled v2 манифестов,
  одновременно принимает произвольные внешние v1/v2 пакеты и не заменяет
  повреждённый выбранный язык legacy-описанием. Исторические ID/LANGID
  резервируются только для совместимости с прежними EXE, профилями и без-bundle
  установками. Конкретные новые коды (AR/EL/PT) не добавлялись в таблицы Python.
- Проверка горячих клавиш перед сохранением учитывает не только работающий,
  но и загружающийся движок. При смене активного набора исключён конфликт
  освободившейся после перезапуска клавиши с ещё работающим языком; новые
  активные языки требуют полного перезапуска mapper, а не скрытой hot-swap.
- v2 personal alphabet policy доставляется из verified manifest в описание
  языка и проверку UserLexicon. Старый формат личных слов RU/EN/HE, v1 sidecar
  и legacy нормализация для v1 описаний сохранены.
- Добавлены интеграционные AR lifecycle, настоящая скрытая Tk панель с AR v2,
  полный install/update/remove/restore именно v2 AR, независимые EL/PT
  policies и fault-injection сценарии. Все действия с
  файлами/профилями тестов ограничены `TemporaryDirectory`.
- После независимого аудита исправлены: fail-closed для отсутствующего
  выбранного пакета (вместо внутреннего TypeError), конфликт клавиши поиска
  с фактически ещё работающим/загружающимся языком (проверка ДО записи,
  доставка настройки hook после успеха), и пользовательское сообщение о
  восстановлении старого journal в GUI/headless до установки hook.
- Исходники ещё не установлены в Public/Diagnostics EXE; физическая No01
  приёмка и frozen executable validation не проводились. Подробности:
  `docs/R16-4G-SOURCE-MODULARITY.md`.
- Итоговая повторная регрессия по финальным исходникам: **486/486 тестов,
  51/51 модуль, 0 ошибок**, полноразмерное RU/EN/HE lexical parity с legacy
  `semantic_equal=true`, cold/warm cache `built/hit`; три безопасных нативных
  private-desktop стенда пройдены (без физической клавиатуры и глобальных
  hooks). Резервный снимок 221 файла проверен по SHA-256; Public/Diagnostics
  EXE и действующие процессы не менялись.

### R16/4f — каталог выбранных пакетов, совместимость профилей и безопасный replay (29 октября 2026)

- Выбранные языки unified runtime теперь собираются из описаний и словарей
  проверенных пакетных объектов. Историческая RU/EN/HE классификация и
  fallback из старого `data/` отделены в compatibility adapter. Повреждение
  выбранного bundled v2 пакета остаётся строгой ошибкой; неактивные внешние
  пакеты в решении не участвуют. GUI inventory всё ещё сохраняет отдельные
  зарезервированные описания базовых языков — полная миграция не объявлена.
- Настройки GUI/HKL и личный словарь используют каталог кодов при наличии,
  включая внешний-only активный набор; начальный язык личного словаря
  выбирается из активных. Универсальная карта сочетаний хранится в основном
  `settings.json`, но старые `direct_ru/en/he` и sidecar v1 записываются для
  совместимости с ранее разосланными EXE.
- Caret-helper больше не импортирует тяжёлый словарный движок для получения
  трёх исторических LANGID. Tray default берётся из общего реестра языков.
- Package manager убрал вложенную блокировку private ZIP staging, journal
  получил привязку к каталогу, дополнительные проверки целостности и путей.
  Старый незавершённый journal без этих данных вызывает безопасный отказ
  с инструкцией ручного восстановления, а не автоматическую потерю архива.
- Тесты только исходные/изолированные. Работающие EXE не пересобирались;
  **466/466 тестов (43 модуля)** пройдены; реальный RU/EN/HE словарь,
  confident, exclusions совпали с независимым legacy, кэш `built/hit`.
  Физическая No01 и фактический portable-release gate открыты. Подробнее:
  `docs/R16-4F-CATALOG-AND-COMPATIBILITY.md`.

### R16/4e — аварийный журнал пакетов и точная диагностика (29 октября 2026)

- Введён `language_package_transactions.py`: межпроцессная блокировка,
  проверки SHA-256 и восстанавливаемый журнал стадий install/update/remove/
  restore. Стартовые GUI/headless-пути восстанавливают незавершённые
  операции до перечня пакетов и установки hook. Неоднозначное или подменённое
  состояние отвергается; при другом работающем TypeBridge восстановление,
  меняющее каталоги, блокируется. См. раздел о пределах гарантий Windows ниже.
- Публикация нового пакета и обновления имеет определённую точку фиксации
  после успешного переименования. Повторное восстановление идемпотентно;
  добавлены fault-injection и имитации обрыва процесса между файловыми шагами.
  ZIP-установка теперь может безопасно создать отсутствующий пустой каталог
  внешних языков после проверки его родительского пути.
- Диагностика `PolicyDecisionEngine` теперь по запросу получает причину
  непосредственно в ветви принятия/отказа полного или раннего решения.
  Обычный callback не трассирует ввод, не пишет пользовательский текст и
  сохраняет прежние вердикты и моменты раннего распознавания.
- Основной source runtime передаёт каталог языков через единый путь;
  специальная классификация bundled RU/EN/HE сосредоточена в явно
  названном compatibility adapter. Уточнены имена проблемных файлов
  confidence в ошибках загрузки и реальные пути словарей в диагностике.
- При чистом запуске, если дискового журнала ещё нет, recovery не создаёт
  пустой каталог транзакций и lock-файл. Этот побочный эффект обнаружен
  отдельным контрольным прогоном и устранён.
- Эти изменения **не устанавливались** в действующие Public/Diagnostics EXE.
  Модельная регрессия и source-level проверки не являются подтверждением
  физического No01, гарантией пережить любой power loss или выпуском релиза.
  Полная итоговая регрессия: **453/453 теста (40 модулей)**. Реальные словари
  RU/EN/HE, confident и исключения повторно сравнивались с legacy —
  тождественны; кэш `built/hit`.
  Legacy storage/projection и каталог-резервация RU/EN/HE остаются открытой
  частью универсализации. Детали: `docs/R16-4E-RECOVERY-AND-DIAGNOSTICS.md`.

### R16/4d — декларативные RU/EN/HE, универсальный профиль и package lifecycle (29 октября 2026)

- Сгенерированы полные `bundled_language_packs/{ru,en,he}` по строгой v2
  schema из уже лицензированных источников приложения. Все прежние
  особенности (RU `ё/е`, HE `he_custom` с двумя нормализаторами, весь
  `SAMPLE_HEBREW`, приоритеты/конечные формы/раннее исправление) теперь
  записаны в манифесты и дополнительный словарный файл, не Python-ветку.
- Основной unified `LanguageEngine` загружает новые базовые языки тем же
  верификатором, что и внешние пакеты; недоступный выбранный пакет даёт
  строгий отказ, неактивный пакет не читается. Полноразмерная семантическая
  old/new проверка совпала по всем множествам RU/EN/HE, cold/warm cache
  `built/hit`. Для старых распакованных программ оставлен отдельный
  file-backed fallback и независимый legacy backend.
- Новое универсальное `language_shortcuts` (`code`→`chord`) хранится в
  основном settings.json как необязательное поле с сохранением назначений
  временно отсутствующих языков. `settings_languages.json` продолжает
  записываться в v1, чтобы прежний EXE мог его читать; экспериментальный
  sidecar v2 новый loader также понимает. Old EXE игнорирует новое поле
  и видит прежние поля RU/EN/HE. Запись двух файлов остаётся с журналом.
- Отдельно устранена опасность попадания локальных приватных слов из
  `data/he_custom.txt` в базовый пакет: экспортируется только публичный
  baseline из `prepare_open_data.py`, private overlay остаётся локальным.
  Сгенерированная папка `bundled_language_packs/` игнорируется Git.
- При нескольких одновременно работающих TypeBridge менеджер отказывает
  в горячем обновлении/удалении даже неактивных пакетов: он не может
  достоверно определить активные языки другого hook-экземпляра.
- `language_package_manager` расширен: safe staged ZIP update, архивное
  удаление, восстановление, защита активных/используемых языков, rollback при
  ошибке публикации и сохранение личных файлов. GUI предоставляет операции.
- Обновлены локальный и релизный билд-пути для поставки bundled v2 рядом
  с бинарником, с проверкой манифестов. **Фактический EXE не пересобран**.
- Offline `decision_diagnostics.py` классифицирует причины `None` без
  влияния на решения или запись пользовательского ввода.
- R16/4 целиком не закрыт: historical registry/fallback, crash journal
  пакетов, полная сборочная и физическая No01 приёмка. Документация:
  `docs/R16-4D-DECLARATIVE-PACKAGES.md`.

### R16/4c — единая политика языков в реальном source runtime (29 октября 2026)

- `LanguageEngine` по умолчанию использует `language_unified_runtime.prepare_selected`
  и независимый `language_decision_v2.PolicyDecisionEngine` для всех
  активных RU/EN/HE/v1/v2 языков; `engine_backend='legacy'` сохраняет
  исходный механизм. Ранние решения теперь идут через ту же policy;
  immutable base и быстрый personal overlay остаются.
- `language_pack_loader.discover_language_packs` распознаёт v1/v2;
  selected-only fail-closed. v1 адаптер сохраняет скриптовую проверку,
  `casefold` и консервативный запрет угадывания между кандидатами.
- Унифицировано содержимое словарей, источников и source-bound `words-v2-*`
  кэша. По полноразмерным RU/EN/HE словарям результат совпадает побуквенно,
  cold/warm cache проверены. Legacy `words-v1.cache` остаётся для отката.
- Новый `language_package_manager` устанавливает data-only пакет из
  директории или ZIP через проверяемый staging и публикацию без замены;
  настроечная активация пользуется предыдущей восстанавливаемой транзакцией.
  В GUI добавлена кнопка установки ZIP с обязательным перезапуском.
- Source/model тесты подтвердили совместимость раннего ввода и решений
  в смешанных наборах RU/EN/HE/AR/ES, personal words/exclusions, GUI,
  HKL-check, LiveHook-модели, Undo, безопасный отказ при ошибках пакетов.
  Работающий пользовательский EXE/hook/HKL и личные файлы не менялись.
- R16/4 **не завершён**: legacy metadata/storage adapters для RU/EN/HE,
  универсальные hotkeys/settings, обновление/удаление пакетов, физический
  No01 остаются отдельными этапами. Подробности в
  `docs/R16-4C-UNIFIED-RUNTIME.md`.

### R16/4b — отдельный v2 parser, lexicon и decision engine (29 октября 2026)

- Добавлен read-only `language_pack_v2.py` со строгими JSON/schema-policy,
  Unicode, SHA256, размером, именами и проверкой безопасной структуры
  каждого пакета. Повреждённый неактивный пакет не читается.
- Добавлен `language_lexicon_v2.py`, полностью декларативно объединяющий
  словари/дополнения по языковым правилам v2, без вызова legacy loader.
- Добавлен независимый `language_decision_v2.py`, не импортирующий
  `LanguageEngine`/`incremental_recognition`: лексические и ранние решения
  выбираются по проверенной v2 policy каждого языка.
- Временный экспорт RU/EN/HE сравнен с legacy на **полноразмерных**
  read-only словарях `dist/data`: все слова/уверенные/exclusions тождественны.
  Золотые 19 decisions, 133 префикса и 160 сгенерированных дополнительных
  сценариев также совпали (в том числе отказы). Это model parity, не No01.
- Все нововведения изолированы от действующего TypeBridge/GUI/hook;
  схему v2 не поддерживает текущая установленная сборка. Кэш/установка v2,
  конвертация личных слов и физическая приёмка — следующие этапы.
  Документ: `docs/R16-4B-PARALLEL.md`.

### R16/4a — аудит правил и проект единого language-pack v2 (29 октября 2026)

- Документированы языковые и общесистемные правила RU/EN/HE: Unicode,
  normalizers для словарей и personal, специальные OEM/VK, `ё/е`, confidence,
  alternatives, early prefix, source veto, кэш, настройки, HKL и Undo.
- Обнаружено важное implicit поведение `he_custom.txt`: он **и words, и
  confident** (`for_words=True` по умолчанию); в обеих ролях используются
  разные нормализаторы. Формат v2 задаёт их раздельно.
- Подготовлена строгая JSON Schema **проектной** версии 2 и policy-only
  snapshots для RU/EN/HE; нет ни установки языков, ни изменения v1 loader.
- Зафиксированы наблюдения старого движка: 19 полных решений и 133
  префикса. Добавлен comparator, проверяющий отказы и текст причины, а
  также умышленно испорченные решения для тестирования детектора регрессий.
  Отдельный новый движок ещё **не подключён**, потому old/new parity
  **не заявляется**. Данные, EXE, HKL, hook, Git remote не менялись.

### R16/3b/5 — подготовка отдельного тестового окна шести направлений (29 октября 2026)

- Добавлен `r16_six_direction_trial.py`: безопасный `--plan` по умолчанию,
  шестисценарная матрица RU↔EN↔HE, отдельный Win32 EDIT для будущего
  **разрешённого** теста реальных физических клавиш, чтение текста и HKL

- Отдельный синтетический режим использует ограниченные `SendInput`-пары
  и запускается только при явном токене и наличии особого тестового
  `TypeBridge --headless --accept-injected` без конкурирующей рабочей версии.
  Его результаты маркируются как **не физическая приёмка**.
- Ни один интерактивный режим или клавиатурный hook при подготовке не
  запускался; текущая раскладка, пользовательские файлы и EXE не изменялись.
  Подробности: `docs/R16-SIX-DIRECTION-TRIAL.md`.

### R16 — изоляция неисправных языков и безопасная сборка (29 октября 2026)

- P1 №7: GUI обнаруживает установленные пакеты с независимым результатом

  помощника за 4 секунды без чтения текста, смены фокуса и установки hooks.
  Это инженерная проверка, не независимая сертификация защиты паролей.
- Транспортные тесты отделены от частотности корпуса: HE-карантин изолирует
  реальный EN `lf`, а OEM-фикстура явно задаёт уверенность «вьюга».

### Также добавлено 24 октября до этого релиза

- Защита через отдельный PowerShell/UIA-помощник: признак `IsPassword` фокусного
  элемента и предков, события фокуса и изменения свойства. В keyboard callback
  нет UIA/COM-вызовов и ожидания; проверяется короткоживущий снимок метаданных.
- В «Горячих клавишах» отображаются прочитанные системные сочетания переключения
  языка/раскладки. «Изменить в Windows…» открывает штатные настройки;
  TypeBridge не переписывает эти значения реестра.

## 2026-10-23

Изменения этого дня выходили поэтапно; список не означает, что они все были
в первой alpha.1.

### Распознавание и замена

- Экспериментальный ранний режим расширен с Notepad++ на проверяемый RichEdit
  и общий клавиатурный SendInput-путь. Распознавание слов сохранено;
  дополнительная настройка для других приложений выключена по умолчанию.
- Исправлен Undo для иврита в нативном RichEdit-пути; поддержан RichEditD2DPT
  современного Блокнота. На границе слова и при ручной команде также используется
  проверяемая прямая замена, без возврата к Backspace при неопределённой записи.
- В первом нативном опыте `EM_REPLACESEL` восстанавливал слово через Undo лишь
  в 4/6 направлениях; при EN/RU→HE оставалась пустота. COM/TOM-группировка,
  запись TOM-диапазона и plain-text RichEdit проблему в том опыте не решили.
  Переход к `WM_CHAR` с `EM_STOPGROUPTYPING` восстановил Undo/Redo во всех
  шести направлениях стенда; COM-путь без доказанного дедлайна `early_tom.py` удалён.
- Для нативного расширения прошли 63 узкие проверки, runtime в другом процессе
  на неактивном Windows desktop — 6/6 направлений, разделитель и два сценария
  следующего слова. Это доставка `WM_CHAR`, не SendInput и не физический ввод.
- В разрешённом видимом автоматизированном опыте проверены RU→EN с продолжением,
  EN→RU и RU→HE. После исправления Undo подтверждено
  `флгщ → שלום → Ctrl+Z → флгщ → Ctrl+Y → שלום`.
  Стенд закрыт, hooks сняты; максимальный темп физической клавиатуры не проверен.
- Отдельный исследовательский стенд `early_keyboard_probe.py` моделировал
  SendInput-пачки, отложенный хвост и подтверждение результата: 15 тестов.
  В `early_keyboard_native_probe.py` получатели EDIT/RichEdit прошли 12/12
  направлений синтетическими сообщениями, без SendInput/foreground/hooks.
  В том опыте Undo EDIT убирал лишь последнюю букву, а RichEdit не всегда
  восстанавливал удержанный символ. Это не результаты готового рабочего транспорта.
  Очередь и guard этого эксперимента в основной переключатель не переносились.
- После регрессии с `ghbпривет` отменена попытка всегда брать HKL главного окна.
  Пользователь позднее подтвердил работу в Блокноте на нескольких языках,
  а в ChatGPT и Notepad++ — раннюю замену и продолжение до `приветик `.
- OEM-знаки исходной раскладки допускаются в раннем распознавании:
  модельный случай `ghj,ktvf → проблема` проходит до пробела.
- Однобуквенные слова на границе слова больше не ограничены «а/и»:
  принимается единственный словарный вариант с сохранением защиты от неоднозначности.
- Из локального HE-словаря в карантин убраны 260 записей с конечными буквами
  внутри слова, отвергнутых Hspell. В локальной базе устранена ложная
  неоднозначность `lf → да`; открытая база может давать другой результат.
- Добавлены опциональное исправление случайного CapsLock `пРИВЕТ → Привет`
  для RU/EN и окно автозамен/литеральных шаблонов: регистр, мгновенное
  разворачивание либо замена после разделителя, многострочные значения.

### Дополнительные возможности

- Быстрый поиск выделения: настраиваемые сервисы, Google как пример,
  горячая клавиша Ctrl+Alt+G. Общий резервный Ctrl+C-путь с сохранением
  поддерживаемых форматов буфера и предпросмотром. Исправлена работа с
  bitmap/PNG/DIB и OLE-служебными форматами. Пользователь подтвердил поиск
  из Notepad++; встроенные/связанные OLE-объекты остаются ограничением.
- Независимые отключаемые история текстового буфера в памяти и вставка без
  форматирования. Настраиваемые сочетания, просмотр/очистка истории из трея.
- Дневник снимков текста известных редакторов, выключенный по умолчанию:
  Notepad/Notepad++, DPAPI, локальная SQLite, срок хранения и самоочистка.
- Импорт исключений TXT/JSON с предпросмотром и объединением без дублей;
  приложены примеры CSpell/MIT для программирования и игровых терминов.
- Категории исключений: менеджеры паролей, IDE/терминалы, графика/видео/звук,
  личный список процессов. Исключения проверяются до перехвата команд.

### Интерфейс и распространение

- Имя TypeBridge, лицензия MIT для собственного кода, публичный репозиторий;
  отдельные лицензии словарей. Инструкции RU/EN/HE и первый portable ZIP
  [v0.1.0-alpha.1](https://github.com/lavalava45/TypeBridge/releases/tag/v0.1.0-alpha.1).
- Локализация настроек, трея и вспомогательных окон RU/EN/HE с переключением
  без перезапуска; правое выравнивание и зеркальные строки для иврита.
- Один флажок «Включить автоисправление» вместо отдельных кнопок запуска/остановки;
  исправлено сохранение `corrections_enabled` и восстановление при запуске.
- Настраиваемая клавиша исправления набираемого слова, по умолчанию Scroll Lock;
  уточнены подписи сохранения, автозапуска и фильтра нескольких заголовков окон.
- Переключатель флажка у каретки доступен непосредственно из трея.
- Добавлены отключаемый автозапуск в трее, пояснения приватности и диагностика
  сбоев интерфейса без записи текста пользователя.
- Пользователь исключил «альтернативные словарные наборы» из обязательной очереди.

## Ранее — базовая реализация

- Словарное автоматическое исправление RU/EN/HE на границе слова, сохранение
  регистра и пунктуации, равнозначность е/ё при русском словарном поиске.
- Опциональное исправление до пробела в Notepad++/Scintilla; сохранена рабочая
  контрольная точка `working-early-checkpoint-20261022` вне репозитория.
- Ручной цикл последнего слова по настраиваемой клавише Pause;
  прямые настраиваемые сочетания RU/EN/HE (Ctrl+Shift+F1/F2/F3 по умолчанию).
- Личные слова и исключения с точным регистром, применение без перезапуска.
- Флаг в трее, ручной выбор установленных раскладок, отключаемый флаг у каретки.
  Индикатор скрывается, если приложение не предоставляет надёжные координаты.
- Исключения процессов, ограничение по заголовкам окон, нативная защита
  Win32 password-полей и защита от конкурирующего запуска.
