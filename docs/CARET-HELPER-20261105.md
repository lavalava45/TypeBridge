# Индикатор каретки: повторные ошибки запуска — 05.11.2026

## Подтверждённый дефект

Пользователь наблюдал мелькающее сообщение `Failed to start embedded python
interpreter`; после выхода из TypeBridge сообщения прекратились. До выхода
наблюдалась смена PID дочернего процесса `--multiprocessing-fork`.

`CaretProcess.snapshot` при смене HWND уничтожает помощника и сбрасывает
`retry_at/failures`. Модель с фиксированным временем подтвердила: повтор в том
же окне блокируется backoff, но чередование двух окон разрешает четыре запуска
подряд. Смена фокуса также отменяла старт процесса ещё до получения `ready`.
Ошибки читателя сохранялись в `reader_error`, тогда как GUI проверял только
`error`; состояние reader не доходило до штатного сообщения.

Эта логика существовала до последнего R02-патча. Источник первого отказа
встроенного Python **не установлен**: старая установленная сборка при проверке
прошла synthetic frozen self-test, включая запуск помощника. Подтверждения
удаления runtime, повреждения архива или вмешательства антивируса нет.

## Исправление

- Здоровый процесс сохраняется между scope/окнами; запуск отменяется по
  завершению приложения или выключению индикатора. При смене фокуса ответ
  дочитывается в ограниченный срок и отбрасывается, не попадая в overlay.
- Backoff сохраняется при смене окна. После трёх последовательных отказов
  процесс больше не запускается; явное выключение/включение индикатора
  разрешает новую попытку. Повторное `set_enabled(True)` бюджет не сбрасывает.
- Перед frozen spawn проверяется наличие `base_library.zip` и `python312.dll`.
  Отсутствие файла останавливает попытки до запуска bootloader.
- Для каждого отказа сохраняются тип исключения, фаза, доступный код выхода,
  наличие runtime и номер попытки. GUI пишет новые записи в
  `dist/TypeBridge-data/replacement-diagnostics.log`; терминальная ошибка
  reader отображается однократно. Текст поля и клавиатурный ввод не логируются.
- Frozen smoke test делает второй synthetic-запрос с другим scope и требует
  тот же PID. Это не проверка физического ввода или реального UIA-провайдера.
