# Совместимость с настольными редакторами

Этап от 31 октября 2026 года. Порядок пользователя: **настольные веб-интерфейсы
→ офисные редакторы → остальные интерфейсные библиотеки**. Браузерная приёмка
на этом этапе не расширяется. Наличие процесса/класса в примере не даёт разрешения
обрабатывать поле и не означает пользовательскую приёмку приложения.

## Что реализовано

Общий клавиатурный путь SendInput обслуживает раннее исправление, исправление
после разделителя, ручное исправление и перебор слова. Существующие специальные
транспорты Scintilla и NativeEdit сохранены; отдельного транспортного плагина
для Word, Electron, Qt или WPF не требуется.

- Состояния отказа ранней клавиатурной замены и RichEdit разделены. Карантин
  NativeEdit или отложенная нативная попытка больше не отключают исправление
  в другом редакторе через SendInput. Собственные частичные отправки/неподтверждённый
  HKL блокируют ранний клавиатурный путь; общая авария worker по-прежнему безопасно
  останавливает соответствующие попытки. Потеря очереди клавиш блокирует исходное
  поле независимо от транспорта; другие поля сохраняют доступность. Поведение браузерного
  отказа после смены поля сохранено.
- Вне общих браузерных/WebView HWND UIA допускает также Custom, Pane и ComboBox,
  если активное поле предоставляет writable ValuePattern либо TextPattern
  с явно редактируемым текущим выделением/кареткой. Тот же признак проверяется
  для Document/Edit без ValuePattern в этой настольной ветке. Одного класса
  окна, имени программы или наличия TextPattern недостаточно.
- Читаются метаданные текущего выделения, а не его текст и не весь офисный
  документ. Методы GetText/Value не вызываются. Неизвестное/смешанное значение
  read-only, несколько выделений и неподдерживаемый provider не разрешают замену.
- ES_PASSWORD, UIA IsPassword, Runtime ID, свежесть, повторная проверка перед
  SendInput и пользовательские исключения сохранены. IDE и терминалы из
  категорий исключений автоматически не включаются.

[Microsoft: TextPattern.IsReadOnlyAttribute](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.textpattern.isreadonlyattribute?view=netframework-4.8.1)
описывает чтение атрибута диапазона через GetAttributeValue. В этой реализации
запрашивается атрибут только текущего единственного выделения, без GetText.

## Покрытие проверки

| Очередь | Семейство | Модельные представители | Путь |
|---|---|---|---|
| 1 | Настольный веб-интерфейс | Chrome_WidgetWin_1 в notes.exe | UIA элемента + SendInput |
| 2 | Офисный редактор | _WwG / winword.exe, SALFRAME / soffice.bin | Метаданные редактируемого поля + SendInput |
| 3 | Другие библиотеки | Qt5152QWindowIcon, HwndWrapper, Microsoft.UI.Content.DesktopChildSiteBridge | Метаданные редактируемого поля + SendInput |

`test_desktop_editors.py` проверяет реальные LiveHook/context/построение пакетов
при **подменённых Win32 и provider**, все шесть направлений автоматической
и ручной замены, ранний путь после карантина RichEdit, обратную изоляцию,
пароли, неизвестную идентичность и исключения. C# UIA-политика компилируется
из действующего helper; её предикат проверяется отдельно без активного UIA.
Дополнительные регрессии покрывают рабочие очереди, частичную отправку,
перебор слова и R04. Итог: **155 целевых теста + 45 тестов движка/нативного пути
успешны**. Полный репозиторный прогон заново не выполнялся.

## Что пока не доказано

Реальные Word/LibreOffice/Qt/WPF/WinUI/Electron-приложения в этом проходе не
запускались и пользовательский ввод не перехватывался. SendInput подтверждает
доставку событий, а не фактический текст и Undo в чужом документе. Нужна живая
проверка продолжения слова, быстрого ввода, Backspace, Undo/Redo, смены фокуса,
разметки и HKL — по одному представителю каждой группы, в указанном порядке,
с отдельным разрешением на фокус/ввод. Критерии No01 и R04 этим не закрываются.

Поля только с MSAA/LegacyIAccessible без подходящих UIA-метаданных, canvas-редакторы,
нестандартные сочетания клавиш и неподдерживаемые providers не объявляются
универсально поддержанными. Не обходить их неизвестное состояние разрешением
по имени EXE. Браузерная матрица остаётся отдельной задачей.

## Дополнение живой приёмки — 31.10.2026

Пользователь подтвердил исправление слова «привет» в Word с английской и
ивритской раскладок на русскую. Время относительно пробела и Undo/Redo для
этих Word-попыток отдельно не подтверждены. В настольном ChatGPT пользователь
подтвердил `ghbdtn → привет`; журнал от 17:37 UTC показал раннюю замену после
шестой буквы, подтверждённый русский HKL и следующий пробел без повторной
замены. Это положительные отдельные сценарии, а не закрытие всей матрицы.

Предыдущие отказы ChatGPT сопровождались `backspace-unknown-span` /
`token-blocked`, а в другие моменты — непроверенным UIA-состоянием. Совпадение
по времени не доказывает единую причину всех пропусков. Правка Backspace
восстанавливает только известное слово из памяти; неизвестный текст и
неподтверждённое поле по-прежнему запрещают замену. Фактическое положение
каретки и документ через новый механизм не считываются; сохраняются общие
ограничения SendInput при неявных изменениях документа самим приложением.
