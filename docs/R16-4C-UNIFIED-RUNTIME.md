# R16/4c — единый runtime-путь языков (исходники, не релиз)

Дата: 2026-10-29. Статус: **реально интегрировано в исходный `LanguageEngine`**,
но **не пересобиралось в рабочий Public/Diagnostics EXE**. Нельзя считать
архитектурную миграцию R16/4 законченной или физический No01 проверенным.

## Что работает в новых исходниках

| Область | Интегрированный путь | Обратная совместимость |
|---|---|---|
| `LanguageEngine` | По умолчанию `engine_backend='unified'`: `language_unified_runtime.prepare_selected()` + `PolicyDecisionEngine` | Явный `engine_backend='legacy'` оставляет прежнюю ветку для проверки и отката |
| RU/EN/HE | Проходят через тот же `UnifiedLanguage` интерфейс, источник словарей, политики уверенности, раннего ввода и кэш, что и другие языки | Исторический `builtin_language()` пока материализует декларативную политику из старых файлов `dist/data` и из `SAMPLE_HEBREW`, а не из отдельного устанавливаемого архива |
| Внешние v1 | Автоматически адаптируются в UnifiedLanguage с `casefold` и `reject_multiple` | v1 манифесты и словари, личные слова и каталоги не переписываются |
| Внешние v2 | `language_pack_loader.discover_language_packs` принимает schema v2 через строгий `language_pack_v2.load_v2_pack` | Старый загрузчик v1 остаётся доступен, формат v2 содержит только данные, не исполняемый код |
| Словари и кэш | Одна выбранная последовательность 1–3 языков; один `words/confident/exclusions` loader и source-verified `words-v2-*` | `words-v1.cache` не переписывается; прежний `load_selected_lexicon` остаётся для отката |
| Решения | `decide`, `decide_token`, `resolve_ambiguity` делегируются независимому `PolicyDecisionEngine`; финальное поведение и `reason` сохраняются | Legacy methods доступны в legacy backend |
| Ранний ввод | `suggest_live_early` делегируется policy engine; существующий immutable sorted base + малый `PrefixOverlay` сохраняется для производительности | Общая инфраструктура построения/обновления index ещё совместно используется с legacy; условие `ё/е` перенесено на декларативный alias |
| GUI | Каталог показывает валидные v1/v2, максимум три активных, кнопка установки ZIP с сообщением о перезапуске | Уже работающий LiveHook/набор языка не меняется в момент установки |
| Управление | `language_package_manager.install_directory/install_zip` публикует в каталоге только проверенные data-only packages, без замены существующих; `save_active_selection` использует прежнюю recoverable settings-pair transaction и проверку уже загруженных Windows HKL | Никаких принудительных перезапусков/hook, личных слов и автозапуска не меняет |

## Безопасное подключение языка без перекомпиляции

Для **исходной версии после штатной сборки** новый язык v1 или v2 требует
только поддерживаемый `code`, совместимый Windows LANGID, надёжные лицензии,
UTF-8 словари и валидный declarative manifest; Python-файл для нового
стандартного языка не нужен. Скрипты и неизвестные файлы внутри пакета
отвергаются. Для сложных новых правил, которых ещё нет в фиксированном
наборе normalizers, необходим отдельный контролируемый релиз ядра; нельзя
разрешать произвольный Python-код или небезопасные правила в манифестах.

**Установка ZIP:**

1. Открыть настройки — «Языки автопереключения» — «Установить языковой
   пакет ZIP…» (доступно только после отдельной пересборки новых исходников).
2. Выбрать ZIP формата `code/manifest.json`, `code/words.txt`, …; внутри
   только декларативные JSON и `.txt/.md`. Проверяются размеры/хэши,
   дубликаты, вредоносные пути, символические ссылки, LANGID, лицензия и
   содержание перед атомарной публикацией папки.
3. Полностью выйти из TypeBridge через трей и запустить снова; новый язык
   появится в списке установленного, но **сам не активируется**.
4. Выбрать от 1 до 3 языков, сохранить настройки; если нужные Windows HKL не
   установлены/недоступны, сохранение нового набора будет отклонено. Ещё
   один полный перезапуск применит набор к hook.
5. Снятие галочки с языка его **отключает**, но не удаляет установленный
   пакет, пользовательские слова, исключения и горячие клавиши.

Нормальная установка **не перезаписывает** существующий пакет. Обновления и
удаление пакетов с возможностью восстановления — отдельная ещё не законченная
функция, прежде чем считать менеджер полностью готовым.

CLI API для офлайновых задач (не установочный сценарий для пользователя):
`language_package_manager.install_zip(path, installed_root)`;
`install_directory(source, installed_root)`;
`save_active_selection(settings_path, installed_root, languages)`.

## Доказательства и регрессия

- Старый и новый путь с одинаковыми **реальными** словарями из
  `dist/data` (только для чтения) сформировали *тождественные множества*
  RU **1 414 532**, EN **176 157**, HE **185 358** и все confident
  RU **39 379**, EN **35 000**, HE **45 000**. Установленные EXE и профили
  не менялись. Кэш: `built` / `hit`. Отчёт:
  `build/r16-4c-integrated-real-parity-20261029.json`.
- Сохранены golden 19 `Decision|None`, 133 префикса и 160 сгенерированных
  сценариев R16/4b; новые интеграционные тесты сравнивают итоговое решение
  и каждый ранний префикс для 9 смешанных наборов, включая RU/EN/HE,
  EN/AR, EN/ES, RU/AR, EN/RU/ES, EN/AR/ES и личные слова.
- Модельные тесты `test_r16_unified_runtime.py` проверяют установку ZIP,
  вторую проверку источников, отказ при подмене содержимого/неверном
  Unicode script, неактивный испорченный пакет, двойной нормализатор
  иврита, source-bound кэш и сохранение данных неактивных языков.
- GUI, загрузка/сохранение и восстановление профилей, конфликты hotkeys,
  LiveHook на модели, Undo, шесть направлений и нативный Win32 редактор
  проверяются существующими регрессиями; изолированный private desktop
  и другие unit-модели **не** считаются физическим тестированием.

## Что осталось историческим и почему

1. `language_registry.py` и `builtin_language()` всё ещё знают, что RU/EN/HE
   поставляются вместе с TypeBridge. Исторические словари по-прежнему в
   `dist/data`, а `SAMPLE_HEBREW` и дополнения встроены в compatibility
   adapter. **Полностью независимые установочные v2-пакеты RU/EN/HE ещё не
   созданы**, в частности из-за необходимости аудита лицензий. Значит,
   R16/4 нельзя считать полностью завершённым.
2. `settings.json`/`settings_languages.json`, `user_lexicon.json`/
   `user_lexicon_packages.json` остаются legacy storage с безопасными
   миграционными адаптерами; GUI и direct hotkeys имеют отдельные RU/EN/HE
   поля для старых профилей. Отсутствие универсального хранилища —
   следующий этап R16/4d.
3. Старые методы `LanguageEngine` и legacy cache оставлены **намеренно**
   для безопасного отката. Подготовка раннего `PrefixOverlay` и native
   transaction transport пока совместно используются обеими реализациями:
   их нельзя менять без отдельного тестирования производительности/Undo.
4. Менеджер пакетов пока умеет установку/активацию/отключение, но **не**
   безопасное обновление с rollback или деинсталляцию. GUI-установка
   появится только в следующем собранном EXE; сейчас она в исходниках.
5. Нестандартные physical VK, непроверенные Windows HKL, AR RTL и ES/EN
   shared Latin script нуждаются в дополнительных нативных и физических
   проверках. No01 остаётся **BLOCKED_PENDING_PHYSICAL_INPUT**.

Пользовательские настройки, работающие EXE, HKL/фокус и глобальный hook не
