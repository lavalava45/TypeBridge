# R17: контекст вне клавиатурного callback — 05.11.2026

## Изменение

`ClipboardHotkeys.handle` больше не вызывает `layouts.capture` или
`target_allowed`/psutil. Отдельный metadata worker готовит неизменяемый
`PreparedContext`: исходный target, объект settings, generation и время
начала проверки. До потенциально блокирующего вызова прежний кэш очищается.
Результат публикуется только при совпадении настроек, поколения и активного
поля, пока worker не остановлен и возраст результата не превышает 200 мс.

Callback выполняет только разбор события/модификаторов, проверку этого кэша,
короткую сверку foreground HWND, focus HWND, PID/TID через Win32 и отправку
команды в существующую очередь GUI. В нём нет поиска имени процесса,
определения класса окна, HKL, UIA, ожидания фонового reader или оконных сообщений
чужому приложению. После live-сверки возраст и generation проверяются повторно.

Если проверка ещё не готова, устарела или не совпала, исходные KEYDOWN/KEYUP
получает приложение. Никакого повторного ввода или запоминания команды для
позднего исполнения нет. Поэтому сразу после смены окна сочетание может
пройти приложению, пока не готов новый контекст.

## Границы безопасности

- Смена настроек сразу очищает кэш; поздний результат прежней проверки его
  не восстанавливает. Зависший reader не создаёт дополнительные readers при
  перезапуске владельца hook; новый запуск отказывается до завершения старого.
- Парольные менеджеры, пользовательские исключения и ошибки метаданных
  не создают разрешающий контекст.
- Кэш подтверждает только маршрутизацию hotkey, **не** безопасность парольного
  поля. Исходные свежие проверки UIA/IsPassword в QuickSearch сохранены;
  cache не заменяет их и не разрешает чтение текста.
- Same-HWND DOM identity и HWND lifetime атомарными не стали. Короткие Win32
  вызовы в callback остаются; абсолютная верхняя граница задержки и факт
  отсутствия тихого снятия hook системой здесь не доказаны.

## Проверка

```powershell
py -3.12 -B -m unittest test_hotkey_context test_clipboard_hotkeys test_clipboard_tools.TrayHotkeyTests test_app_exclusions.ClipboardRoutingTests test_r18_console_fallback test_clipboard_selection test_quick_search.SearchTests test_tray_recovery test_tray_layouts test_r04_native_target_lease test_r04_addressed_prototype test_r04_default_text_target test_early_native_edit test_caret_process test_caret_indicator test_p0_five_findings -q
```

208 успешных исполнений, 3.406 секунды. Новые модели проверяют блокирующий
capture, отсутствие process lookup внутри callback, устаревшие данные,
смену settings/generation/focus/PID, запрет поздней публикации и дубля worker,
парольный менеджер и пользовательское исключение. Настоящие hooks, физический
ввод, clipboard и смена фокуса не использовались; bitmap-тесты используют
собственные GDI-объекты. Установленная программа перед сборкой закрыта пользователем.

  остаётся в исходниках, но runtime не передаёт `experimental_target_lease=True`.

Сборка и проверка её манифестов фиксируются в [STATUS](STATUS.md) после
завершения штатного `build-typebridge.ps1`. Новый GitHub Release или тег
этой задачей автоматически не создаётся: R04/No01 остаются существенными
незакрытыми критериями стабильной приёмки. Alpha-кандидат должен явно сохранять
эти ограничения; старый release CI не проверяет новые коммиты.
