## Результаты проверки существующих механизмов

| Механизм | Что действительно есть | Почему нельзя подключить как готовую замену выделения |
| --- | --- | --- |
| `quick_search.read_selection`, UIA | Возвращает строку выделения, сохраняет края | Нет адреса диапазона, его границ и подтверждения неизменности выделения перед записью |
| `clipboard_selection.copy_transaction` | Snapshot/restore поддержанных форматов по sequence/owner; чтение после Copy | Возвращает `SearchPreview(text.strip())`: теряет пробелы/переносы по краям; Copy сам по себе не доказывает наличие выделения |
| `NativeEditBridge` | `EM_GETSEL`, преобразования UTF-16/UTF-8, проверки идентичности и bounded messages | Путь замены рассчитан на слово: максимум 32 знака вне hook; табуляция, переносы и emoji отвергаются; текущая нормализация RichEdit CRLF не универсальна |
| `ScintillaEarlyBridge` | Нативный BEGIN/ENDUNDOACTION и адресный REPLACETARGET | `snapshot()` отвергает некратное каретке выделение; подготовка ограничена 256 байтами и нынешним расположением буфера |
| Plain paste | Поддерживает обычную вставку и восстановление буфера при доказанном отказе | Проверка окна не фиксирует границы выделения; нельзя использовать готовую вставку как подтверждённую замену нужного диапазона |

Это ограничения применимости существующих методов, а не ошибки их поискового
или раннего словарного назначения. Например, `strip()` корректен для поискового
запроса; изменять поведение поиска ради R10 не нужно.

Реальные вызовы с подменёнными API подтвердили:

- Copy-preview из ` \tghbdtn\r\n ` возвращает `ghbdtn`; восстановление буфера
  вызывается, но точного исходного выделения уже нет.
- UIA-путь поиска возвращает ту же строку без обрезания, но только строку.
- Native prepare принимает маленькое `hello`, отвергает перенос, TAB, emoji
  и 33-символьную замену в текущем worker-режиме до редактирования.
- Scintilla snapshot при активном выделении возвращает отказ
  `selection-or-document-limit`.

## Контрпример старого ручного пакета

В модели исходный документ — `PREFIX ghbdtn SUFFIX`, выделено только `ghbdtn`.
В памяти ручной команды ещё находится это слово; уведомление о новом выделении
не поступило. Вызван настоящий `_cycle_word` через Pause с подменённым SendInput.

Первый Backspace удаляет сразу всё выделение, следующие пять — часть префикса.
Получается `PRעינגאמ SUFFIX`. Префикс повреждён, суффикс сохранён.

Это **модель конкретного состояния**, не доказательство, что обычное выделение
мышью всегда вызывает дефект: существующий mouse hook обычно сбрасывает память.
Сценарий показывает, почему нельзя направить R10 на старую Backspace-замену
при неотслеженном/программном изменении выделения. В текущем обработчике этот
остаточный сценарий на данном этапе не исправлен; нового routing там нет.
Диагностический скрипт не делает такой пакет на настоящем рабочем столе.

## Что подготовлено

`selection_cycle.py` не импортируется рабочим приложением. Это ядро и контракт
нового адаптера, без clipboard, UIA, HWND, SendInput или собственного чтения поля:

- `SelectionSnapshot` хранит точный выбранный текст, anchor/caret, идентичность
  адресата и ревизию фокуса. Единицы позиций обозначены явно: codepoint, UTF-16
  либо UTF-8. Длина диапазона обязана совпадать с длиной текста в этих единицах.
  Весь документ не требуется; логический предел выделения — 2000 знаков.
- `SelectionCycle` восстанавливает физические клавиши по исходной раскладке,
  не обращаясь к словарю. Повторный цикл использует эти же клавиши, сохраняя
  регистр даже при неоднозначном обратном отображении промежуточной раскладки.
  Если исходная клавиша не определяется однозначно по тексту, выбор
  детерминирован: сначала unshifted, затем минимальный VK.
- Пробелы, CR/LF, TAB и непереводимые символы, включая emoji, сохраняются точно.
  Пунктуация, представленная физической клавишей исходной раскладки, тоже
  переключается: это может быть буква целевого языка. При отсутствующем
  отображении целевой клавиши операция целиком отклоняется до записи.
- Поддержаны прямое/обратное выделение и сохранение подсветки после замены.
  Владелец и номер шага запрещают старому результату продвинуть другую операцию
  или воскреснуть после полного RU/EN/HE цикла.
- `replace_selection` дважды проверяет исходный snapshot до записи, требует
  подтверждения выбранного результата и не повторяет запись/Undo при
  неопределённом исходе. Отказ либо неопределённость закрывает старый цикл.

Источник языка передаётся ядру явно. Определение языка произвольного выделения
и правило для смешанного текста в рабочем контроллере ещё не реализованы.
Текущее ядро сохраняет символы, не представимые в явно указанной исходной
раскладке; оно не обещает независимо распознать и исправить каждый язык внутри
одного смешанного выделения.

## Проверки и их границы

11 unit-тестов с in-memory диапазонным редактором прошли:

- Шесть направлений RU/EN/HE × три системы координат, с emoji перед выделением;
  точные пробелы/переносы/TAB и неизменность префикса/суффикса.
- Полный повторный цикл с регистром, emoji и символами без клавиатурного аналога;
  обратное выделение сохраняется.
- Одна операция Undo и Redo **в модели**.
- Смена выделения между подготовкой и записью, другой адресат/ревизия,
  несовместимые позиции, пустое и слишком длинное выделение.
- Частичный write/timeout без повтора или слепого Undo; неподтверждённый readback
  не продвигает язык; старый план после полного круга отвергается.

Модельный редактор сам реализует идеальную атомарную замену и стек Undo.
**Это не проверка Undo в RichEdit, Chrome или другом реальном редакторе.**
Без реального адаптера нельзя считать R10 готовой функцией или объявлять
сохранёнными форматирование документа/буфера и Undo во всех приложениях.

## Следующий этап реализации

1. Адаптер должен различать точное пустое выделение, положительно прочитанный
   диапазон и недоступность чтения. Ошибка чтения не означает «выделения нет»;
   после начатой замены выделения нельзя пробовать старый путь слова.
2. Для native/Scintilla отдельно реализовать snapshot выбранного диапазона,
   подходящие ограниченные буферы, сохранение подсветки и реальную Undo-группу.
   Не расширять лимиты старого word-bridge и не читать весь документ по привычке.
3. Для обычных браузерных полей нужен собственный точный reader/adapter;
   поисковая строка и один Ctrl+V не являются его готовым эквивалентом. Проверить
   смену выделения во время ожидания, multiline и Undo на настоящем редакторе.
4. Только затем подключать приоритет выделения в ту же команду Pause вне
   callback, с существующей очередью владельца и без новой клавиши/галки.
   Существующую политику допуска обычного ввода этот подготовительный этап
   не изменяет. Новая сборка здесь не выполнялась.
