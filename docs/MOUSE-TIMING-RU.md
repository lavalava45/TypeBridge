# Измерение задержек мышиного callback

В исходниках и профиле Diagnostics включённый режим диагностики добавляет
в существующие события `pipeline:watchdog` два числовых поля:

- `mouse_max_us` — максимальная длительность мышиного Python-callback за время
  работы hook, в микросекундах, включая передачу события через CallNextHookEx.
- `mouse_slow` — количество вызовов длительностью от 5000 микросекунд.

Для этих счётчиков достаточно `TypeBridge-debug.flag`; запись слов не требуется.
Они не содержат координат, текста или отдельных записей каждого движения.
Обычный путь без диагностики использует прежний обработчик мыши.

Эти значения **не включают ожидание GIL до входа в Python** и не измеряют
задержку от физического движения до обновления экрана. Даже низкие значения
не доказывают отсутствия задержек в системе.

Изолированный тест ctypes с подставным CallNextHookEx может показать стоимость
входа в Python и влияние конкурирующего Python-потока. Его результаты нельзя
выдавать за измерение настоящего WH_MOUSE_LL или работу конкретной мыши.
Смена интервала GIL и архитектуры мышиного hook этим изменением не выполняется.
