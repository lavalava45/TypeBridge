# R02: восстановление слова у каретки — 05.11.2026

## Проблема

`גיאהז` соответствует `время` по тем же физическим клавишам. Движок со
словарями распознаёт эту замену однозначно. Отказы возникали раньше словаря:
после Backspace по неотслеживаемому тексту блокировался оставшийся токен;
при неизвестном статусе поля первый префикс не запоминался. После пробела
Pause мог использовать только `last_word`, которого в этих случаях нет.

## Изменение

- Если отслеживание потеряно, на пробеле выполняется отдельная попытка получить
  целое слово у каретки и заново проверить его словарём.
- Pause при отсутствии подходящего сохранённого слова получает целое слово
  у каретки, включая уже набранные пробелы, затем использует прежний ручной цикл.
- Пустое ручное исправление Scroll Lock больше не уничтожает память слова,
  нужную для последующего Pause.
- Отказ чтения при автоматическом восстановлении пропускает один пробел
  и позволяет нормально отслеживать следующее слово.

Чтение запускается в worker после подтверждённого возврата callback. Обычный
отслеживаемый токен и Pause с действующим `last_word` не требуют нового чтения.

## Проверки безопасности

Новый `caret_word_recovery.py` использует отдельный скрытый процесс с лимитом
2,5 секунды. Перед чтением требуются актуальная разрешённая ревизия guard и
конкретный `uia:` Runtime ID. Helper проверяет тот же HWND/фокус/Runtime ID,
IsPassword и предков, единственную свёрнутую каретку. Выделение не изменяется.

Читается только ограниченный диапазон около каретки; ValuePattern и текст всего
DocumentRange не читаются. Принимается не более 81 UTF-16 единицы слева и двух
справа; немного больший лимит GetText позволяет обнаружить переполнение вместо
незаметного усечения конца диапазона. При изменении диапазона или каретки
результат отвергается. Слово — 1–40 букв, суффикс — до 40 пробелов/NBSP;
неполный токен и неоднозначное обратное сопоставление клавиш отвергаются.

Перед/после чтения проверяются поле, guard, настройки, язык, полный HKL и
ревизия браузерного поля. Новые клавиши задерживаются существующей очередью.
Unknown/password/stale, другой элемент, недоступный TextPattern, тайм-аут и
ошибка провайдера не разрешают изменение. Буфер обмена не используется,
символы из непроверенного поля не сохраняются для последующего угадывания.
Полученный текст не пишется новым reader в журнал или на диск.

## Проверка и ограничения

Расширенный прогон: **222 теста прошли**, включая обычные WordCycle/AppControls.
После добавления восстановления при пустом токене без флага блокировки выполнен
финальный целевой прогон: **179 тестов прошли**, включая 16 новых проверок в
`test_caret_word_recovery.py`. После уточнения лимитов GetText синтаксические
и parser-проверки reader отдельно повторены (5/5).

`test_caret_word_recovery.py` проверяет реальную карту HE/RU и словарь для
`גיאהז → время`, пробел после неизвестного Backspace, пропущенные первые буквы,
Pause до/после пробела, обычный путь без чтения, отказ провайдера с возобновлением
следующего слова, сохранность памяти после Scroll Lock, пароль/смену элемента,
ограничения парсера и тайм-аут. PowerShell проверен синтаксическим парсером без
выполнения UIA. Интеграции используют подменённые API и документ в памяти.

Реальный браузер, его UIA provider, физическая клавиатура, IME и Undo/Redo в этом
проходе не испытывались. Fallback требует TextPattern и проверенного UIA ID;
если provider их не даёт, исправление не выполняется. Основное неатомарное окно
проверки/SendInput R04 не устранено. Ранний путь до пробела не восстанавливает
непроверенные префиксы; физические R01–R03/No01 остаются открытыми.
