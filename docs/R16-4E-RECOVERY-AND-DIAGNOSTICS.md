# R16/4e — аварийные транзакции, диагностика из алгоритма и универсальный запуск

**Дата:** 29 октября 2026 года. **Применимость:** изменения в исходниках,
не в работающих Public/Diagnostics EXE. Ввод с физической клавиатуры,
пользовательский HKL и глобальный hook не проверялись и не изменялись.
Статус приёмки No01: `BLOCKED_PENDING_PHYSICAL_INPUT`.

## Принцип разделения нового и старого пути

`LanguageEngine(engine_backend='unified')` обрабатывает выбранные языки через
`language_unified_runtime` и декларативный `PolicyDecisionEngine`. Для
распространяемых RU/EN/HE при наличии `bundled_language_packs/` используется
тот же строгий v2 parser, что для внешнего v2-пакета. Неактивные повреждённые
пакеты не входят в расчёт; повреждённый выбранный пакет не заменяется молча.

Изолированные механизмы старых версий сохраняются сознательно: явный
`engine_backend='legacy'`, совместимый формат `settings_languages.json` v1,
старые поля RU/EN/HE, `words-v1.cache` и file-backed adapter, если в старом
дистрибутиве отсутствуют базовые v2-пакеты. Это **не** правила для новых
внешних языков и не разрешение загружать исполняемые компоненты из пакетов.

## Жизненный цикл пакетов и журнал восстановления

Модули `language_package_manager.py` и `language_package_transactions.py`
сериализуют изменения посредством межпроцессной блокировки. Журнал хранится
в соседнем каталоге `language_pack_transactions/` отдельно от проверяемого
каталога `language_packs/`; архив предыдущей версии — в
`language_pack_history/`.

1. Проверяется структура источника/ZIP, манифест, содержимое, коллизии
   идентификаторов языков и защита активного набора.
2. До переименования сохраняется запись с контрольными SHA-256 исходного
   пакета и, когда применимо, подготавливаемой версии. Записи стадий
   сбрасываются на диск (`flush`/`fsync`) и заменяются атомарно.
3. Установка публикует проверенный пакет без неявной замены существующего;
   обновление архивирует старую папку до публикации новой; удаление переносит
   её в историю, а восстановление возвращает только проверенный архив.
4. При следующем запуске исходников journal replay выполняется **до**
   обнаружения пакетов и создания hook. Повторный replay идемпотентен;
   отсутствие, подмена или неоднозначная пара исходного/архивного каталога
   приводит к явному безопасному отказу, а не удалению словарей наугад.
5. Восстановление запрещено для языка работающего hook. Если запущен другой
   TypeBridge и его активные языки нельзя проверить, изменяющее файлы
   восстановление блокируется. Операции GUI требуют полного перезапуска
   для применения нового каталога языков.

При отсутствии журнала первый запуск не создаёт служебный каталог и файл
блокировки только ради проверки восстановления. Этот случай отдельно покрыт
тестом без записи в реальный профиль.

Это покрывает **проверяемые сценарии аварийного завершения процесса** между
действиями файловой системы. На Windows нельзя обещать абсолютную
устойчивость к внезапному отключению питания: `fsync` файла не обеспечивает
доказанной долговечности переименования каталога при любом файловом
контроллере/кэше. После такого события предусмотрена строгая проверка
целостности и остановка при противоречиях.

Журнал не содержит пользовательские слова или введённый текст, только
служебные пути, стадии и отпечатки файлов. Личные слова, исключения и
назначения горячих клавиш не удаляются вместе с пакетом.

## Точные причины решений

`PolicyDecisionEngine.diagnose_token()` и `diagnose_early()` выполняют
отдельный диагностический проход с причинами, полученными непосредственно
из отказных ветвей алгоритма. Адаптеры
`decision_diagnostics.explain_token(..., exact_policy=True)` и
`explain_early(..., exact_policy=True)` позволяют включить это поведение
по запросу; прежняя постфактум-классификация остаётся для совместимости.

Коды охватывают известное исходное слово, исключение, пустой набор
кандидатов, недостаточную уверенность, конкурирующие назначения,
недопустимые физические клавиши/Unicode, префиксы и пунктуацию. Это не
новая политика исправлений: обычные `decide`/`decide_token` и ранняя выдача
не начинают записывать трассировку, а диагностическая функция не входит
в обычный callback. Пользовательский ввод на диск не записывается.

## Проверки и остаточные ограничения

Регрессионная матрица включает исторические golden-решения, ранние префиксы,
все **85 упорядоченных наборов** из 1–3 RU/EN/HE/AR/ES, offline
fault-injection для всех операций с пакетами, настройки, персональные слова,
кэш, GUI/LiveHook-модели и сборочные проверки без создания EXE. Точные
результаты текущего повторного прогона сохраняются в
`build/r16-4e-full-regression-final-20261029.log`: **453/453 теста,
40/40 модулей, 0 ошибок**. Предыдущий прогон (до отдельного исправления
пустого startup journal) сохранён в
`build/r16-4e-full-regression-20261029.log`: **452/452**.

Повторная полноразмерная проверка без Windows hook и физического HKL,
выполненная `python fixtures/r16_4e_real_parity.py`, подтвердила
побуквенное совпадение `words`, `confident`, `exclusions` unified и legacy:
RU **1 414 532 / 39 379**, EN **176 157 / 35 000**,
HE **185 358 / 45 000** (слова / уверенные слова). Холодный/тёплый
кэш — `built/hit`. Отчёт без пользовательских слов:
`build/r16-4e-real-parity-20261029.json`.

Без отдельного разрешения не выполнялись: остановка работающего TypeBridge,
пересборка/замена EXE, публикация релиза, реальный ввод, смена HKL,
установка hook, Git commit/push. Не пройдены физическая No01-приёмка и
валидация нового портативного EXE. Крошечные AR/ES-пакеты в `fixtures/`
остаются тестовыми примерами, а не производственными словарями.
