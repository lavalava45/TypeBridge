# Выбор словарного режима TypeBridge — малая воспроизводимая проверка (06.11.2026)

**Рекомендация: сохранить `conservative=True` по умолчанию.** На приведённых
25 заранее выбранных сценариях ослабление до `False` устранило один пропуск
(`rdfynjdfybt` → `квантование`) и не вызвало наблюдаемых ложных замен.
Но эта маленькая, вручную отобранная выборка не оценивает реальную частоту
ложных исправлений и не доказывает оптимальность любого режима. Включать
`False` для всех пользователей на основании этой проверки преждевременно.

## Как воспроизвести

Из корня репозитория на Windows с Python 3.12:

```powershell
py -3.12 -B experiments/dictionary_mode_evaluation_20261106.py
```

Скрипт импортирует реальный `LanguageEngine`, проверяет наличие файлов
`data/{ru,en,he}.txt` и `data/confident_{ru,en,he}.txt`, загружает штатные
словари из `engine.source_data_dir()`, затем для **одних и тех же** физических
клавиш и текущей раскладки вызывает `decide_token()` при
`conservative=True` и `conservative=False` (оба раза `allow_rare=False`).
Он не модифицирует словари, конфигурацию, hook, раскладку Windows или GUI.
Переиспользуемый движок переключает только `engine.conservative`; штатная
синхронизация политики происходит внутри `decide_token`.

В таблице **Keys** — обозначения физических клавиш американской раскладки,
**HKL** — имитируемая текущая раскладка, **Typed** — строка, полученная
в этой раскладке. **Expected** — заранее вручную заданное намерение человека.
**OK** — получен ожидаемый результат, **MISS** — нужное исправление не сделано,
**FP** — выполнено неверное или нежелательное исправление. Эти категории
описывают только выбранные сценарии, не показатели точности продукта.

## Интерпретация и ограничения

- Для `tot` специально заданы **два противоречивых человеческих намерения**
  при одинаковых клавишах и HKL: сохранить английское `tot` или получить
  русское `еще`. Без контекста невозможно одновременно удовлетворить оба;
  один `MISS` в таблице — демонстрация неоднозначности, а не доказанная
  ошибка алгоритма для реальной пользовательской частоты.
- Случаи имён и технических терминов вручную подобраны и частично выглядят
  как обычные английские слова. Их сохранение не доказывает безопасность
  для редких имён, сокращений, кода, URL, сленга или идентификаторов.
- Редкие слова включены целенаправленно для поиска различий между режимами,
  поэтому доля пропусков и разница режимов заведомо не отражают реальное
  распределение набираемых пользователями слов. **Ни одна выборка не была
  случайной или репрезентативной**, доверительные интервалы не вычислялись.
- Размеры файлов или число слов в словарях не используются как оценка
  покрытия реальных текстов. Разница между режимами зависит также от
  словаря уверенных совпадений, неоднозначности и правила сохранения
  известного исходного слова.
- Оценивалось словарное решение `decide_token()` на фиксированных вводах.
  Не проверялись ранние исправления до пробела, Undo, реальные клавиатурные
  события, физический HKL, фокус, браузеры, Spotify и безопасность записи.

Для обоснованной смены значения по умолчанию нужен заранее зафиксированный
корпус естественных фрагментов с помеченным намерением, включая ошибочные
раскладки и правильно набранные имена/технические токены; отдельные обучающая
и отложенная выборки, слепая проверка ложных замен и сравнение RU/EN/HE по
разным типам токенов. До такого опыта разумно оставить `conservative=True`
и использовать ручное переключение для слов, которые автоматика пропускает.
