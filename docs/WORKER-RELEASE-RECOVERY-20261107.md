## Исправлены два модельно подтверждённых дефекта

1. При безопасной отмене command-транзакции отложенные Pause/KEYUP попадали
   в recovery, хотя сама команда намеренно поглощена и возвращать нечего.
   Недавно добавленный запрет новых транзакций при pending recovery превращал
   это в общую блокировку запусков. Теперь поглощённые trigger-события исключены
   из recovery; для его создания нужен хотя бы один возвращаемый KEYDOWN.
   Настоящий печатный ввод после команды сохраняется, без автоматической досылки.
2. Если native preflight отказывал до вызова released_job, его finally не
   очищал `_keyboard_job_release`. Добавлен serial-aware `on_finished` для
   native worker и отказа старта потока. Старое завершение не очищает слот
   более новой команды.

В диагностику добавлено различение `pending-input-recovery` и
`pending-callback-release`. Текущий старый EXE этих причин ещё не пишет;
какая из отметок блокировала конкретно его, из имеющегося журнала не доказано.
Интервал возобновления совместим с прежним трёхминутным сроком pending recovery,
но сам по себе не является доказательством её содержимого.
