# R16/4f — выбранные языки из проверенных пакетов и границы совместимости

**Дата:** 29 октября 2026 года. **Статус:** исходники TypeBridge,
не пользовательские Public/Diagnostics EXE. Физический No01 и portable
frozen-приёмка **не выполнены**. Работающий hook/HKL/фокус не менялись.

## Проверенные источники языков

Новый `LanguageEngine(engine_backend='unified')` получает активные записи
через `language_unified_runtime._selected_package_sources()`: описания,
источники словарей, приоритеты и политики выбранных языков вычисляются из
верифицированных объектов установленных и bundled v2 пакетов. Неактивные
внешние словари не читаются, выбранный отсутствующий/повреждённый пакет
отклоняется. Для активного набора 1–3 языков нет фиксированного перечня
внешних кодов и отдельной альтернативной decision-ветки для AR/ES.

Историческая RU/EN/HE резервация LANGID и `language_registry` остаётся в
явном адаптере `_compat_builtin_source_plan()`, который защищает имена и
исходные LANGID и предоставляет flat-file fallback только в старом
дистрибутиве **без каталога** bundled. Если bundled-каталог имеется,
повреждённый выбранный RU/EN/HE пакет **не** заменяется тихо legacy-данными.
Изолированный `engine_backend='legacy'` сохраняется для проверки отката.

Полностью динамический GUI-inventory пока не завершён: при перечислении
доступных языков `available_language_catalog()` использует зарезервированные
описания RU/EN/HE и проверенные внешние установленные пакеты. Этим нельзя
обосновать удаление compatibility registry. Обобщение этой части требует
отдельной проверки времени запуска, отсутствия чтения испорченных неактивных
пакетов и согласованности старых профилей.

## Настройки, HKL, горячие клавиши и личные слова

Новый рабочий GUI использует проверенный каталог, когда он доступен, для
проверки выбранных Windows HKL, сохранения настроек и загрузки личных
словарей. При внешнем-only активном наборе начальный язык редактора личных
слов выбирается из этого набора, а не принудительно RU. Универсальная карта
`language_shortcuts` включает выключенные/временно отсутствующие языки,
но их назначения не захватывают события, пока язык не активирован.

Намеренно оставлены `direct_ru/direct_en/direct_he` и формат основного
`settings.json`, понятные старому EXE. Sidecar `settings_languages.json`
**записывается в формате v1** — изменение этого формата на v2 нарушает
совместимость ранее распространённых программ. Чтение ранее созданного
экспериментального sidecar v2 сохраняется, но не делает его форматом записи.
Главный JSON хранит универсальную карту дополнительных сочетаний.

## Отдельная периферия

`caret_indicator.py` и `caret_process.py` больше не импортируют `engine`
ради значений LANGID; читают лёгкие метаданные `language_registry`. В
обычном runtime им передаётся фактическое соответствие выбранных языков.
`tray_win32.py` использует общий `DEFAULT_ACTIVE_LANGUAGES` вместо
повторяющихся литералов RU/EN/HE. Имеющиеся тесты проверяют оба режима.

## Журнал операций с пакетами — укрепление R16/4e

`language_package_manager.py` более не создаёт отдельную вложенную
межпроцессную блокировку при подготовке private ZIP staging для update;
внешняя транзакция остаётся единственным сериализатором публикации.
`language_package_transactions.py` привязывает новый journal к исходному
корню установки, контролирует структуру служебной папки, пути истории,
неожиданные payload и метаданные целостности. SHA-256 journal обнаруживает
повреждение, но **не является цифровой подписью или аутентификацией**.

В R16/4e использовался журнал версии 1 без привязки к корню и без собственной
контрольной суммы. При обнаружении такого *незавершённого* журнала R16/4f
останавливает автоматический replay: **файлы пакетов, историю и журнал не
перезаписывает и не удаляет**. Для восстановления необходимы проверенная
резервная копия и ручное сопоставление истории, файлов и их отпечатков.
Слепое разрешение старого журнала ослабило бы безопасность путей. Это
важное ограничение обновления исходников, а не гарантия recovery через
любую несовместимую версию журнала.

Включены отказные тесты установки, архивирования, replay, чужого пути,
неожиданного файла, контрольной суммы, старого journal и запуск без
транзакций. Настоящий power-loss на Windows не моделировался и не заявлен.

и unit/integration сценариях без глобальных hooks и физической клавиатуры.
