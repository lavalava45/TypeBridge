## Подтверждённые проблемы и правки

1. **Коррекция на `-` и `+` (исправлено в исходниках).** До правки эти
   символы приводили к `nonword-key` и отключали распознавание продолжения.
   Добавлены границы `-+` и тесты `Rfrjt-n` / `vfif+cfif`.
   Затем независимая ревизия нашла регрессию `x-ghbdtn`:
   хвост неизвестного идентификатора ошибочно корректировался. После
   уточнения state machine хвост блокируется, если префикс перед `-`/`+`
   не был исправлен. Отдельные тесты проверяют `x-ghbdtn`, `x+ghbdtn`,
   `hello-ghbdtn`, `hello+ghbdtn` и обычные английские слова.
   Файлы: `typebridge_app.py`, `test_word_cycle.py`, `test_punctuation_runtime.py`.
2. **Лишний Win32 вызов в simple mode (исправлено в исходниках).**
   `LiveHook._correct()` вызывал `GetClassNameW` до проверки
   `self.simple_mode`, хотя для generic/SendInput транспорта класс не нужен.
   Теперь класс запрашивается только вне простого режима. Добавлен
   маршрутизирующий тест в `test_desktop_editors.py`. Это устранение
   вызова, НЕ замеренная на реальном Chrome экономия миллисекунд.
3. **Неверная подпись GUI (исправлена без изменения поведения).**
   `exclusions_gui.py` утверждал, что менеджеры паролей «всегда исключены»,
   что неверно в simple mode. Теперь интерфейс явно указывает действующее
   намеренное ограничение. Password guard не активирован.
4. **Недостаточная диагностика frozen UIA (улучшена без активации guard).**
   `self_test()` скрывал различие между COM typelib import, synthetic child
   spawn и IPC. Добавлены `uia_helper_stage` / `uia_helper_failure` только
   с кодами стадий/типами ошибок, без UIA-содержимого, HWND и пользовательского
   текста. `build_profiles.frozen_smoke_test()` при ошибке показывает только
   разрешённые коды. Файлы: `typebridge_app.py`, `uia_native_worker.py`,
   `build_profiles.py`. Это не включает парольную политику.

## Наблюдения по старому PasswordFieldGuard (только обзор)

У strict-пути много обязательных условий (свежий UIA элемент/Runtime ID,
проверка `IsPassword`, ревизия разрешения, асинхронный рабочий процесс и
короткие TTL). При неизвестном или недоступном состоянии он намеренно
отказывает в коррекции. Это объясняет, почему такой дизайн **способен**
массово блокировать обычные нестандартные редакторы при нестабильных
UIA-метаданных; без воспроизведения прежнего окружения точную историческую
причину всех отказов не установить. К защищённому вводу этот путь не
подключён и в ходе аудита не подключался.
