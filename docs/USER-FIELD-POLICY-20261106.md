# Политика неизвестных полей — 06.11.2026

Решение пользователя после отказа новой сборки в Chrome и чате: **разрешать
переключение в неизвестных полях; блокировать только явные признаки пароля**.
Это заменяет прежний запрет `unknown`, требования UIA editable/addressable,
Runtime ID и свежести метаданных как условия допуска клавиатурной коррекции.
Нераспознанное парольное поле тоже может быть исправлено — это принятое
поведение, а не обещание полной защиты паролей.

- `staged_password_guard` включает `explicit_password_only` для обычного GUI
  и headless runtime независимо от старой скрытой галки. Строгий API guard
  сохранён для специальных потребителей метаданных и прежних изолированных
  тестов; пользовательского переключателя строгого режима нет.
- `ES_PASSWORD` и полученное `IsPassword=true` продолжают запрещать текстовые
  команды в соответствующем поле. Неизвестные/просроченные ответы, отсутствие
  helper, неподтверждённая редактируемость и отсутствие UIA ID допускаются.
  Повторная проверка перед SendInput не ждёт нового ответа UIA.
- Появление первого ответа UIA, его потеря и смена editable/addressable не
  сбрасывают уже набранное слово. Смена известной идентичности, фокуса или
  парольного состояния продолжает менять revision и отменять старую операцию.
- Восстановление слова при потерянном отслеживании может само получить
  Runtime ID текущего элемента в своём ограниченном reader. Оно проверяет
  стабильность элемента, фокуса и диапазона. Без поддержки чтения диапазона
  восстановить неизвестный текст невозможно; обычный отслеживаемый ввод
  от такого чтения не зависит.
- Границы слова учитывают физические клавиши букв включённых языков:
  `z|,kj` и `z,|kj` восстанавливают целое `z,kj`, а не только `z`/`kj`.

Проверки без реального ввода: `test_user_field_policy_20261106` (реальные
обработчики автоматики и Pause с подменённым SendInput; все пять положений
каретки в `z,kj`; смена доступности метаданных; явный пароль),
`test_field_states_20261106`, `test_caret_word_recovery`,
`test_p0_guard_transport_integration`, `test_r04_default_text_target`.
Тесты не меняют фокус, пользовательскую раскладку и не устанавливают hooks.
Физическая приёмка Chrome/чата отдельно не объявляется выполненной.

Предыдущая матрица `FIELD-CHECK-MATRIX-20261106.md` и ранние отчёты этого дня
описывают прежний запрет неизвестных полей, а не текущую пользовательскую
политику. R04 атомарность и No01 остаются открытыми.
