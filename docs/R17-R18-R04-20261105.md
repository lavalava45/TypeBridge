# R17, R18, R04 и подготовка снимка — 05.11.2026

## Результат по очереди

1. **R17: исправлен источник задержек от трея.** `ClipboardHotkeys` создаёт
   отдельный message-loop поток. Он создаёт Win32-очередь до готовности,
   устанавливает/снимает hook и применяет команды настроек. Ожидание ограничено
   секундой на готовность и секундой на применение; тайм-аут отключает новые
   перехваты и не разрешает позднему результату снова включить их. Второй поток
   не создаётся, пока первый жив. Отключение дренирует уже поглощённую клавишу;
   перенастройка сверяет пропущенный KEYUP по физическому состоянию вне callback.
   Завершение трея продолжается при ошибке остановки hook worker.
2. **R18: console fallback защищён независимо от исключений.** Перед созданием
   NativeCopy и повторно перед SendInput проверяются классы top/focus и имена
   процессов target/host. Распознаваемые терминалы и неизвестная идентичность
   запрещают Ctrl+C. После метаданных непосредственно перед отправкой снова
   проверяются окно и deadline; задержка метаданных до 30 виртуальных секунд
   не разрешает поздний Ctrl+C. UIA TextPattern-выделение по-прежнему разрешено. Список
   признаков не гарантирует распознавание любого встроенного терминала.
3. **R04: усилен только opt-in прототип.** В lease проверяются не только
   изменяющие сообщения, но и чтение; сменившийся password style/guard
   запрещает следующий WM_GETTEXT. Назначение SendMessage берётся из lease.
   Обычное приложение не передаёт `experimental_target_lease=True`.
4. **Подготовка выпуска: создан снимок исходников для сверки.** Архив, манифест
   SHA-256, патч и метаданные зависимостей находятся локально в
   `build/source-review-20261105/`. Источники runtime и изолированные эксперименты
   разделены по каталогам и указаны в манифесте; `early_native_edit.py` остаётся
   смешанным файлом с выключенным opt-in. Это явное ограничение, а не заявление,
   что эксперимент уже физически вынесен из production-модуля.

## Проверка

```powershell
py -3.12 -B -m unittest test_clipboard_hotkeys test_clipboard_tools.TrayHotkeyTests test_app_exclusions.ClipboardRoutingTests test_r18_console_fallback test_clipboard_selection test_quick_search.SearchTests test_tray_recovery test_r04_native_target_lease test_r04_addressed_prototype test_r04_default_text_target test_early_native_edit -q
```

**160 исполнений, OK, 2.579 секунды**. Win32 hook API и очереди подменены;
используются настоящие Python threads. Clipboard не читается/не меняется;
отдельный существующий bitmap-тест работает с собственными GDI-объектами.
Новые R04-проверки модельные; private desktop в этой задаче не запускался.
`git diff --check` изменённых файлов пройден. Физический ввод не проверялся.

Отдельная модель блокирующего reader удерживает worker на Event до истечения
дедлайна: второй запрос не создаёт дополнительный worker; guard не разрешает
поздний Copy; после освобождения просроченный результат не открывает браузер.
Это **не** принудительное прерывание стороннего API: пока он не вернётся,
QuickSearch остаётся busy. R18 частично открыт.

## Что снимок гарантирует и чего ещё нет

- Архив содержит точные байты отобранных исходников, тестов, build-скриптов,
  `dictionary_packs`, R04-экспериментов и документов. Манифест фиксирует базовый
  HEAD, dirty-состояние, хеши файлов и найденные версии зависимостей.
- Личные настройки, история, журналы, `.env`, EXE и содержимое локальных
  словарных overlays не включаются. Для словарей из текущего build-манифеста
  сохраняются только контрольные суммы: сами данные нужно предоставить
  отдельно с подходящими правами распространения. Поэтому это воспроизводимый
  **снимок исходников**, а не самодостаточный release bundle или обещание
  побайтово воспроизводимого EXE.
- Ранее существовавшие изменения outreach не включены в патч/архив и не
  изменялись. Предыдущий caret-патч и экспериментальный R04 код сохранены.
- Новые изменения не собраны в EXE, не закоммичены, не отправлены и не
  опубликованы. Работающий EXE — предыдущая сборка с исправлением индикатора.

## Открытые критерии

- **R17:** реальный callback latency, shutdown и тихое снятие hook Windows
  требуют отдельной приёмки. Отдельный поток не доказывает живучесть hook;
  capture/exclusion позднее вынесены из callback — см. [продолжение](R17-HOTKEY-CONTEXT-20261105.md).
- **R18:** жёстко блокирующий API нельзя безопасно оборвать внутри процесса.
  Перенос clipboard-транзакции в убиваемый процесс требует самостоятельного
  протокола восстановления буфера; здесь он не заявляется реализованным.
- **R04:** HWND reuse и разные DOM-поля одного HWND не защищены атомарно.
  Повторные проверки чтения уменьшают окно, но не дают lifetime lock.
  Браузерное расширение, инъекция и включение прототипа в live-hook не делались.
- **Выпуск:** нужна сверка/фиксация dirty-состава, сборка и соответствующая
  приёмка; прежний frozen self-test не проверяет новые исходники.

Основание Win32 lifecycle: [LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)
и [PostThreadMessageW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postthreadmessagew).
