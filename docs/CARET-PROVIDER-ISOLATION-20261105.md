# Каретка: изоляция медленного MSAA — 05.11.2026

## Подтверждённая причина каскадного отключения

Native caret и резервный MSAA обслуживаются одним helper. Если native caret
не найден, `AccessibleObjectFromWindow`, `get_accState`, `accLocation` и COM
cleanup могут заблокироваться без нашего внутреннего дедлайна. Родитель
останавливает helper через 300 мс, но раньше три таких отказа отключали весь
индикатор, включая другие окна с исправной native caret.

Это подтверждённая ошибка обработки отказа в коде. Старые логи содержат только
`phase=receive`, поэтому связывать конкретный прежний тайм-аут с одним из этих
COM-вызовов пока нельзя. Ошибка первого запуска интерпретатора тоже не доказана
этим объяснением.

## Исправление

- Geometry-only IPC теперь сообщает этап: native, msaa-object, msaa-state,
  msaa-location, msaa-cleanup. Разрешены только фиксированные поля stage/top;
  текста, имени поля или документа в этих сообщениях нет.
- Progress-пакеты не продлевают дедлайн. После MSAA timeout helper завершается,
  а резервный MSAA для фактически сообщённого HWND top ставится на паузу 60 с.
  На следующей попытке native-only чтение остаётся доступным. Другие окна
  продолжают обычный путь; очередь paused HWND ограничена 32 записями.
- Отказ необязательного MSAA не расходует глобальный бюджет отказов запуска
  интерпретатора. Startup/native/protocol ошибки по-прежнему имеют backoff и
  предел трёх отказов; ошибка отсутствующего runtime сразу запрещает запуск.
- Native-only в окне без native caret возвращает None: флаг скрывается, а не
  остаётся на старом месте. Спустя cooldown MSAA снова разрешён. Явное off/on
  индикатора сбрасывает паузу, как и прежний ручной retry.
- Если native-путь уже потратил более 100 мс, новый неограниченный COM fallback
  не начинается. Общая проверка свежести геометрии 150 мс сохранена.
- COM cleanup выполняется даже при ошибке сообщения о стадии.

В проблемном browser/control без native caret флаг может отсутствовать во время
паузы. Это ограниченное ухудшение конкретного резервного пути; зависший provider
сам по себе не исправлен и не становится прерываемым внутри COM-вызова.

## R04/No01: независимая сверка следующего пути

В текущем [AXPlatformNodeWin Chromium](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/ui/accessibility/platform/ax_platform_node_win.h)
не заявлен `IAccessibleEditableText`; наличие интерфейса в IA2 IDL не означает
его реализацию Chrome. Это ограничивает намеченный кандидат `replaceText`,
но не доказывает отсутствие всех альтернатив или поведение установленной
версии браузера. Нужна отдельная read-only capability проверка конкретного
provider, прежде чем писать новый transport. Замена всего ValuePattern поля
и глобальный SendInput не объявляются атомарным адресным исправлением слова.
R04/No01 остаются открытыми; режим opt-in не включался, защиту паролей не меняли.
