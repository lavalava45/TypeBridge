## Патч 1. Единая ручная команда

- `word_key` — единственный активный выбор на первой странице; прежние
  `manual_key`, `manual_f8` и `cycle_key` читаются и сохраняются для совместимости.
- Приоритет миграции: явный `word_key` → нестандартный `cycle_key` → разрешённый
  нестандартный `manual_key` → разрешённый `manual_key` при выключенном `cycle_key`
  → стандартный `Pause`; если обе старые команды выключены, новая выключена.
- Ручной цикл обходит словарное решение; автоматическое исправление может быть
  выключено. Слово сохраняется после пробелов; UIA-readback читает обе половины
  слова у каретки с проверкой Runtime ID, диапазона и фокуса. `RecentWord`
  хранит относительную позицию каретки при восстановлении внутри слова.
- Обнаружен и исправлен дефект полного жизненного цикла: при снятой галке
  автоматического исправления прежний GUI вообще не запускал hook, хотя
  одиночные тесты обработчика проходили. Теперь включённая ручная клавиша
  запускает обработчик в `paused` режиме, автоматические исправления выключены,
  а `_schedule_keyboard(...allow_paused=True)` допускает ручную операцию и
  ручное восстановление слова. При выключении обеих функций hook не запускается.
- При изменении режима из живого GUI переход `manual-only` ↔ `automatic`
  сохраняет выбор в настройках до отправки команды hook. При ошибке сохранения
  включение автоматики не запускается; выключение автоматики по-прежнему
  останавливает автоматические исправления, даже если запись настроек не удалась.
- Для поля, поддерживающего только глобальный клавиатурный пакет, последующая
  смена HKL и число принятых SendInput не подтверждают содержимое документа.
  GUI больше не объявляет такой пакет проверенной текстовой заменой.

Проверки: `test_unified_manual_20261106`, `test_word_cycle`,
`test_caret_word_recovery`, `test_app_controls`, `test_case_direct_hotkeys`,
`test_ui_i18n`, `test_manual_only_lifecycle_20261106`,
`test_hook_cycle_offhook`. Модель восстановления середины не заменяет живое испытание
редактора и Undo.

## Патч 3. Метаданные поля, адресат и зависание

- Семантика helper-протокола: `state=password` (запрет текста),
  `state=unknown` (неизвестная парольность) и `state=safe, addressable=0`
  (известно, что поле не парольное, но безопасная текстовая доставка
  не подтверждена). Третий вариант не разрешает SendInput.
- Нативный `Edit` внутри браузерного хоста сам по себе не выбирает
  Win32-адресный текстовый транспорт. Browser `Document` с одним лишь
  наличием TextPattern без явно записываемой текущей выборки не разрешён.
- Истёкшие ответы UIA и смена DOM identity/HKL/фокуса не дают разрешения
  на новый адресат; UIA выполняется в отдельном процессе, не в hook callback.
- Неопределённый результат прямой записи в проверенный Win32 HWND
  блокирует это поле; неопределённый общий SendInput/ошибка очереди
  по-прежнему может требовать глобальной остановки транспорта. Отказ до
  запуска редактирования не считается доказательством частичной записи.

Точная таблица OFF/ON: [матрица полей](FIELD-CHECK-MATRIX-20261106.md).
Набор моделей: `test_field_states_20261106`, `test_password_fields`,
`test_r04_default_text_target`, `test_desktop_editors`.

## Отдельный аудит EXE

Работающий PyInstaller `--onefile` использует `_MEI*` для распаковки runtime;
локальная сборка использует другие временные каталоги для проверяемых
кандидатов. Конкретное удаление «временного EXE» не зафиксировано и виновник
не установлен. См. [аудит владения](EXE-TEMP-OWNERSHIP-20261106.md).
Удаление старых `_MEI*` без доказательства владельца запрещено.

## Открытая физическая приёмка и выпуск

Критерии: одиночное набираемое слово; один/несколько пробелов; курсор в
середине; повторный RU→EN→HE→RU цикл; неизвестное слово; автоматика выключена;
сохранение caret/Undo; Chrome/Spotify обычный `input`, `textarea`, редактируемый
`combobox`, read-only, пароль, неизвестный provider; смена фокуса A→B и
A→B→A, задержка ответа UIA и завершение программы под задержкой.

**Не пройдено физически:** клавиша Unified Manual в настоящем пользовательском
поле и Spotify.
Без реального readback нельзя считать глобальный SendInput адресным. R04/No01
остаются OPEN/BLOCKED. Возможные испытания рабочего стола требуют отдельного
разрешения пользователя согласно `AGENTS.md`; виртуальные машины запрещены.
После исчезновения всех процессов прежней сборки штатный `build-typebridge.ps1`
завершился успешно, включая финальную пересборку после исправления GUI-цикла:
Public и Diagnostics прошли frozen self-test **6/6** каждый,
сохранены словари и настройки, а проверенные артефакты опубликованы только в
`dist/TypeBridge.exe` и `dist/profiles/Diagnostics/TypeBridge.exe`.
Проверены SHA-256 по встроенным манифестам; источник содержит **225 Python
файла**, `worktree_dirty=true` (локальная рабочая сборка, не Git-релиз):

- Public SHA-256: `0c21b06a639abd58d7b42a8cc935f955eee86076389e542710537b8679d85ef9`
- Diagnostics SHA-256: `f17ffde24ee0c0dd989383ed945606262ef2c97528d88ab96ce5da357f391b07`

Повторно проверено: **0 несовпадений** SHA-256 среди всех 225 файлов исходного
дерева в манифестах обоих профилей, обе суммы EXE совпадают с манифестами,

полем без доступа к его текущим документам.

Ограниченный настоящий **неактивный private Windows desktop** допустим и уже
использован повторно для теста адресной замены в RichEdit A при неизменности B:
