# R16/4b — параллельный v2-парсер и независимый модуль решений

**Состояние: реализованы и протестированы в offline-модели, без включения
в рабочий TypeBridge.** Дата 2026-10-29. Этот этап *не* является
публикацией новой версии или физической приёмкой No01.

## Реализованные части

| Модуль | Назначение | Что не делает |
|---|---|---|
| `language_pack_v2.py` | Строго загружает schema v2 с проверкой манифеста, SHA256/размеров всех payloads, ограничений, имён, языковых политик и конфликтов LANGID | Не импортируется обычным `language_pack_loader`, не устанавливает пакеты и HKL |
| `language_lexicon_v2.py` | Готовит `words`, `confident`, `exclusions` по атрибутам v2. Разные нормализации для добавлений `for_words` и `for_confident`; безопасно отказывает при изменении проверенных файлов | Не использует `_read_lexical_data`, не создаёт пользовательский или runtime cache, не запускает hook |
| `language_decision_v2.py` | Отдельный алгоритм токенов, неоднозначности и ранних подсказок через набор v2 policy objects; без `LanguageEngine` и `incremental_recognition` | Не выполняет ввод в редакторы, не изменяет настройки, не подключён к GUI |
| `test_r16_4b_parallel.py` | Генерирует **только временные** пакеты из тестовых данных, проверяет негативные сценарии, лексическую и поведенческую эквивалентность | Не заменяет официальные установленные языковые пакеты |

## Какие сохранены исторические правила

- RU: `NFKC + casefold + strip combining + ё→е`; `а`, `и`, `поясни`
  присутствуют в словах **и** уверенных; alias `ё→е` остаётся для ранних
  индексов.
- EN: `NFKC + casefold + strip combining`, `a`, `i` — только обычные слова.
- HE: тот же dictionary normalizer; полная `SAMPLE_HEBREW` входит в оба
  словаря. `he_custom.txt` входит **в оба** словаря; для `words` используется
  словарная NFKC-нормализация, для `confident` — только casefold, включая
  сохранение некоторых Unicode-диакритических знаков.
- Неоднозначность: у старой тройки `ordered_priority`; у AR/ES v2
  явно задаётся `reject_multiple`. Композиция policy отказывается выбирать
  из нескольких кандидатов, если такой режим требует хоть один активный
  пакет. В новом модуле нет проверки `code in LANGUAGE_BY_CODE`.
- Контракты Word Affixes, Unicode script, source veto, confidence,
  пунктуации, early prefix/rare exact и `reason` воспроизведены отдельным
  evaluator. Системный HKL, физический ввод, Undo и scope остаются прежними.

## Подтверждённые сравнения

1. **Тестовые словари:** одинаковые `words`, `confident`, `exclusions`
   для каждого из 15 порядков 1–3 языков RU/EN/HE (3+6+6).
2. **Полноразмерные словари из `dist/data` (только чтение):** legacy
   `_read_lexical_data` и независимый v2 pipeline дали **полностью
   одинаковые** множества, не только одинаковые размеры. Количество
   обычных слов: RU **1 414 532**, EN **176 157**, HE **185 358**.
   Уверенных: RU **39 379**, EN **35 000**, HE **45 000**. Общих
   исключений в этом наборе — 0. Итоговая проверка заняла примерно 19,3 с;
   разовое время нельзя считать репрезентативным бенчмарком.
3. **Старый vs действительно отдельный v2 decision engine:** все
   **19** зафиксированных `Decision | None` совпали со всеми полями,
   включая `reason`; для **133** заранее сохранённых префиксов раннее
   решение также совпало. Отдельно пройдены **160** детерминированных
   сгенерированных моделей с размерами 1–12, меняющимися известностью,
   уверенностью, консервативностью и исключениями; для каждой сравнивались
   полные решения и *каждый* ранний префикс.
4. Ошибочные JSON-поля, неподдерживаемые normalizers, контрольные суммы,
   повторные роли файла, посторонние/исполнимые файлы, нарушения имен,
   несоответствие script/HKL и случай повреждённого отключённого языка
   проверены отдельными отрицательными тестами. Действующая v1 загрузка
   вообще не импортирует v2-код.

Подробный отчёт проверки реальных словарей:
`build/r16-4b-real-dictionaries-parity-20261029.json`.

## Границы доказанного

**Это пока не автоматическая обратная совместимость всех возможных
вводов.** Модельные 19+160 сценариев не покрывают все реальные физические
раскладки, пользовательские словари, Unicode/IME, новые пакеты, прерывание
ввода и взаимодействия с редакторами. Для подключения в GUI/HKL/hook
требуются намного более широкие property/integration tests и отдельная
физическая проверка. R16/No01 остаётся `BLOCKED_PENDING_PHYSICAL_INPUT`.

V2 API в этом этапе **только read-only и без кэша**. Настоящий менеджер
установки/удаления, перенос настроек, совместимые stable cache keys,
необходимая дополнительная проверка физических HKL для нестандартных
`source_nonletter_keys` и сценарии конкурирующих обновлений — следующие
задачи. JSON Schema сама по себе не обеспечивает безопасность: строгий
runtime parser независимо проверяет реальные файлы. Установка v2 не
поддерживается текущим пользователем EXE.

## Следующая граница разработки

1. Углубить parity-тесты: периоды/affixes, специальные VK, personal
   sensitive/insensitive, исключения, ранний ввод в mixed RU/EN/HE/AR/ES,
   и разные реальные keyboard layouts, не трогая пользовательский фокус.
2. Подготовить проверяемый source-bound cache для нового v2 loader без
   дополнительных повторных чтений и без ухудшения контроля целостности.
3. Реализовать совместимый adapter настроек и личных слов, оставить
   текущие data-форматы, затем осторожно вводить opt-in shadow-mode
   нового engine в модельные тесты, но не в обычный hook.
4. Отдельно проверить No01 на физическом вводе. Только после доказательств
   обсуждать переключение рабочей сборки и миграцию на v2.

Нет новых EXE, установленных пакетов, изменений HKL, hook, пользовательских
словарей или автозапуска. Git-коммиты и публикация не выполнялись.
