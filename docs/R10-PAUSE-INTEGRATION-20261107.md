# R10: подключение выделения Scintilla к Pause — 07.11.2026

## Дополнение: повторный Pause без KEYUP (07.11.2026)

Устранена зависимость повторного `VK_PAUSE` от физического `WM_KEYUP`
в общем обработчике `LiveHook.handle_keyboard`. После завершённого
off-hook worker следующий самостоятельный Pause KEYDOWN запускает следующую
команду, даже если `VK_PAUSE` всё ещё есть в `suppressed_keyups`.
Множество по-прежнему подавляет необязательный поздний KEYUP; для
остальных клавиш, включая F9, KEYUP остаётся обязательным для повторного
срабатывания после первого KEYDOWN. Пока native queue занята, повторный
Pause не создаёт второго worker; очередь поглощает его как command trigger.
`Ctrl+Alt+Pause` (переключатель режима) и прямые горячие клавиши
не изменены: для подавления автоповтора по-прежнему ожидают KEYUP.

Новые синтетические регрессии:
`test_pause_no_keyup_20261107.py`. Три Pause KEYDOWN без KEYUP в
слове «яблок» до/после пробела и выделении Scintilla, нормальные
пары KEYDOWN/KEYUP, эксклюзивный worker, F9 без KEYUP и
отсутствие двойного переключения режима Ctrl+Alt+Pause.
До исправления целевые тесты падали; после исправления 7/7 прошли.
Ни одна проверка не использует реальный ввод, hook, раскладку или
пользовательские окна. Запущенный EXE **не пересобирался**.

## Готово в исходниках

В `LiveHook._cycle_word` для Notepad++/Scintilla перед памятью слова
вызывается диапазонный адаптер. Чтение и замена выполняются через существующий
released-callback worker и очередь ввода, с `allow_paused=True`.
В callback нет чтения диапазона, remote allocation или записи редактора.

- Непустое выделение имеет приоритет над устаревшей памятью слова.
- Только подтверждённый пустой диапазон допускает прежний путь слова.
- Повтор команды сохраняет исходные физические клавиши, регистр, направление
  выделения, пробелы/переносы и перебирает активные языки без словаря.
- Клик, обычная клавиша, навигация и clear_token сбрасывают сессию.
  Изменение snapshot, документа, текущего языка, mapper или набора языков
  создаёт новую сессию. Перед записью проверяются фокус, HKL, настройки,
  эпоха сброса и состояние очереди.
- После readback запрашивается HKL результата; сессия сохраняется только при
  подтверждении HKL и прежнего адресата. Неясная запись не повторяется через
  Backspace и не вызывает автоматический Undo или глобальный карантин.

## Проверка

42 узких теста прошли: 12 новых проверок реального обработчика Pause/worker
с модельным Scintilla-транспортом, 19 ранее подготовленных проверок ядра/
адаптера, 8 generic off-hook и 3 manual-only lifecycle.

Проверены приоритет выделения, ожидание выхода callback, полный цикл,
ручной paused-режим, пустое выделение, ошибки чтения и ответа после записи,
смена диапазона/документа/фокуса, навигация, сброс при prepare, отказ запуска
worker и неподтверждённый HKL. Реальный SendInput не вызывается.

Дополнительный `test_desktop_editors` выявил 12 провалившихся subtest в одном
старом тесте `test_password_unknown_and_missing_identity_refuse_desktop_context`:
он ожидает отменённый пользователем запрет unknown/неполных метаданных.
Проверяемый `_context` в этом патче не менялся; сам старый тест не исправлялся.
Остальные проверки этого модуля прошли. Полный suite не запускался.

Предыдущие 15 нативных private-desktop сценариев проверяли сам адаптер и
настоящий Undo/Redo; они не являются физической приёмкой нового подключения.

## Осталось

Физический Pause в настоящем Notepad++, последующая проверка Undo/Redo и
переключения документов; отдельный путь выделения Chrome и других редакторов.
Исходный язык выделения пока берётся из текущей раскладки; автоматическое
определение языка произвольного смешанного выделения не реализовано.
Поддерживается одно обычное выделение UTF-8, до 2000 символов, x64 Notepad++.
Межпроцессные сообщения не атомарны относительно любых сторонних правок;
программные изменения вне выбранного диапазона без событий hook не имеют
универсального счётчика редакций в этом прототипе.

EXE не собирался, приложение не запускалось. Рабочий ввод и clipboard
пользователя не затрагивались. Git commit/push не выполнялись.

## Дополнение: Pause после пробела в Notepad++ — 07.11.2026

В пользовательском тестировании воспроизведён непостоянный отказ Pause
после пробела, иногда на первом, иногда после двух переключений. Точная
причина конкретного живого отказа пока не подтверждена. Словарное
распознавание не является запретом ручного цикла: `RecentWord.next_variant`
берёт сохранённые физические клавиши независимо от словаря. Отдельно
проверено, что `правильно` присутствует в RU-словаре и автоматическое
решение для этого правильно введённого слова — `None`.

Найдена и закрыта конкретная функциональная дыра: при пустом выделении
Scintilla, но утраченной `last_word`, `Pause` пытался использовать UIA
TextPattern вместо прямого чтения уже адресованного Scintilla. Теперь он
восстанавливает слово из ограниченного native snapshot (UTF-8,
подтверждённые каретка и пустое выделение), восстанавливает однозначные
физические клавиши и делает **новый независимый** `replace_prefix` с
проверкой точного исходного текста и суффикса перед записью. Середина
слова, неоднозначная раскладка, неопределённая каретка и сбой чтения
остаются fail-closed; не используется глобальный Backspace/SendInput.

Для ручного off-hook Scintilla-переключения увеличен ограниченный бюджет
чтения/транзакции до 250/450 мс: существующие 45/90 мс оставлены для
ранней коррекции. При отказе native Pause теперь сообщает безопасный код
причины через пользовательский статус, а не только диагностическое событие.

Проверка изолированной моделью: `правильно` + два пробела + другой текст,
без сохранённой памяти, три Pause дают RU → HE → EN → RU с точным
сохранением соседнего текста. Проверка каретки посередине слова обязана
отказать без записи. Эти тесты **не доказывают** поведение физического
Notepad++/HKL; R10 и No01 остаются открыты. Действующий запущенный EXE
не обновлялся.
